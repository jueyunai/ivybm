# IVYBM 一期开发实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在 23 个工作日内交付可上线的英文 / 阿语铝单板官网、统一 Payload CMS、官网 AI 客服与知识库、会话与线索闭环、飞书同步、AI 内容工作台，以及按前置条件分级验收的海外平台连接器。

**Architecture:** 使用一个 Next.js App Router + Payload CMS 模块化单体承载官网、后台、API 和轻量 worker，PostgreSQL 18.4 + pgvector 0.8.5 统一保存内容、会话、线索、任务和知识库。官网、CMS、AI 客服和飞书构成 P0 确定性闭环；WhatsApp / Meta 属于 P1 条件性交付，TikTok 会话与受限平台能力按 P2 调研或半自动流程验收。

**Tech Stack:** Node.js LTS、pnpm、TypeScript、Next.js App Router、Payload CMS、PostgreSQL 18.4、pgvector 0.8.5、Vitest、Playwright、Docker Compose、1Panel OpenResty、外部 AI API、飞书开放平台。

## 0. 执行规则

- 本计划从当前文档基线提交之后开始执行；每个任务独立验证，建议按任务提交。
- 初始化当天使用 Payload 官方脚手架支持的 Node / Next / React 兼容组合，随后由 `.nvmrc`、`package.json#packageManager` 和 `pnpm-lock.yaml` 固定。
- 测试驱动顺序：先写最小失败测试，再实现，再运行任务级测试，最后运行累计质量门禁。
- 第三方平台不阻塞 P0 主链路。P1 无真实授权时使用 fixture / mock / sandbox 完成契约测试，并记录阻塞条件。
- 真实 `.env`、客户数据、平台 token 和云密钥不进 Git；只提交 `.env.example`。
- 每阶段完成后更新 `docs/开发进度.md`。

## 2. 全局完成定义

一期只有同时满足以下条件才视为完成：

1. 英文 / 阿语官网可通过正式 HTTPS 域名访问，核心页面、交互、响应式和 RTL 高保真还原客户确认的 `references/website-prototype/`，视觉回归、SEO 和 CMS 更新正常。
2. 官网询盘和 AI 客服会话可以沉淀线索，高风险问题可转人工，高意向线索能进入飞书。
3. 内容工作台具备生成、人工审核、平台格式化、发布任务和日志，不允许未审核内容直接发布。
4. P0 自有能力全部实测通过；P1 平台按账号与审核条件完成实接或 PoC；P2 有书面技术结论和阻塞证据。
5. 权限、审计、Webhook 验签、幂等、重试、dead job 和人工补偿均有自动化测试。
6. production 镜像、Compose、健康检查、日志轮转、备份恢复和回滚经过验证。
7. 无真实密钥、合同、客户原始资料、数据库和上传文件进入 Git。
8. `docs/acceptance/一期验收清单.md` 无未处理 P0 阻塞项，试运营关键问题已记录并关闭或明确延期。
