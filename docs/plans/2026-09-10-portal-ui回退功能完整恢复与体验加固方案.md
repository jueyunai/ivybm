## 3. 接口与交互契约

### 3.1 首页优先事项深链

```typescript
export const priorityHref = (
  kind: PortalOverviewPriorityItem['kind'],
  id: number | string,
): string => {
  const encodedId = encodeURIComponent(String(id))

  switch (kind) {
    case 'active-conversation':
    case 'handoff-request':
      return '/dashboard/conversations?conversation=' + encodedId
    case 'lead':
      return '/dashboard/leads?lead=' + encodedId
    case 'job':
      return '/dashboard/operations?job=' + encodedId + '#portal-job-' + encodedId
  }
}
```

验收要求：链接不只跳转到模块，目标会话/线索/任务必须被加载、选中或明确高亮。

### 3.2 后台任务定位查询

```typescript
export interface SafeJobQuery {
  job?: number
  page: number
  status: SafeJobStatusFilter
}
```

- `parseSafeJobQuery` 只接受正整数 `job`，无效值按未指定处理；
- 指定 `job` 时使用 Payload 查询权限读取该任务，不用前端 mock 或绕过 access control；
- 目标不存在或不可见时显示普通空状态，不泄露任务是否真实存在。

### 3.3 知识库工作区

```typescript
export type KnowledgeWorkspaceTab = 'documents' | 'debug'
export type KnowledgeWorkspaceDrawer = 'ingest' | null
```

- 默认打开 `documents`；`?tab=debug` 打开 AI 调试；`?drawer=ingest` 打开入库抽屉；
- Tab 必须具有 `tablist/tab/tabpanel`、`aria-selected`、roving `tabIndex` 以及 ArrowLeft/ArrowRight/Home/End 键盘契约；
- 文档列表整行可点击和键盘激活，打开新建/入库态时清除旧文档选中态；
- 入库抽屉关闭后返回触发按钮，移动端不得水平溢出。

### 3.4 弹窗与统一选择器

```tsx
<Dialog.Content className="portal-shell portal-surface portal-modal">
  {/* header, close button, form, actions */}
</Dialog.Content>
```

- `UiSelect` 的可见控件使用 Radix `Trigger` + `Content` + `Item`，展开菜单必须呈现项目统一选中态、悬停态和对勾图标，不再调用操作系统原生下拉菜单；
- Trigger 必须暴露 `role="combobox"`、可访问名称、`aria-expanded` 与 `aria-required`，组件内部不可交互的约束代理负责 `name`、`required` 与 FormData；
- 空字符串只在 Radix 状态机内部映射为 sentinel，对外 `onChange`、FormData 与业务 URL 仍使用真实空字符串；
- 不允许同一字段渲染两套面向用户或自动化测试的可交互选择器；Playwright 和 RTL 统一通过点击 Trigger、定位 `role="listbox"`、选择 `role="option"` 的 helper 操作；
- 鼠标、触控和 ArrowUp/ArrowDown、Home/End、Enter/Space、Escape 必须可用，禁用项不可选择，关闭后焦点回到 Trigger；
- 必填字段传递 `required`，名称、值、浏览器约束校验和表单提交语义与当前后端契约一致；在 Modal/Drawer 内展开不得关闭外层容器。
- Portal 业务源码不得直接渲染 `<select>` 或导入另一套选择器；公开官网询盘的国家选择器不在本次 Portal 边界内。

### 3.6 私有发布素材的审核摘要契约

```typescript
type ApprovedAssetDigest = {
  byteLength: number
  filename: string
  id: number
  mimeType: string
  sha256: string
}
```

- `reviewContentStudioDraft` 在 `decision: 'approved'` 时返回 `approvedAssets: ApprovedAssetDigest[]`；现有路由命令包装器把结果写入 `scope = portal.content-studio:review:<contentID>` 的 `PortalCommandReceipts.result`。
- 发布私有媒体时只信任匹配 `contentID + mediaID` 的最新 `completed` 审核回执。没有摘要、摘要格式无效或字节不匹配均返回 `content-studio-publication-asset-private`，不得公开媒体或创建 `PublishJob`。
- 直接调用审核领域函数不会创建回执；集成测试必须通过路由命令包装器，或显式用审核返回结果创建等价的 completed 回执。
- 本批次采用零 migration 方案：现有 JSON 回执已经处于审核命令的事务和幂等边界内，新增共享 Collection 字段会扩大上线风险且无必要。

### 3.7 Demo Seed 真实性契约

- Portal Demo 仍需 `SEED_PORTAL_DEMO=true` 显式启用，production 环境继续硬阻断。
- 官网渠道的本地回复可以标记 `sent`；没有 provider 回执的 Facebook、Instagram、TikTok 出站消息不得标记 `sent`。

- 新建官网内容时旧列表项不再保留选中高亮。
