# 生产与更新冒烟巡检方案

- 状态：脚本与本地合成验证已完成，待 Portal 测试账号、飞书公开视图人工预检和 production 受控验收
- 生效日期：2026-08-25
- 适用范围：一期 production 首次验收、版本更新后冒烟、后续按需巡检
- 上位基线：[MVP 范围冻结与交付冲刺](./2026-08-10-MVP范围冻结与交付冲刺.md)、[一期 MVP 关键闭环 E2E 测试用例](./2026-08-16-MVP-E2E测试用例.md)

## 1. 目标与验证边界

本方案使用**一个 Playwright 脚本入口**，通过真实浏览器操作验证以下两条 production 主链路可达：

1. 官网询盘 → Portal Lead → 飞书多维表格；
2. 官网 AI 客服 → 人工接管 → Lead → 飞书多维表格。

同一份脚本用于首次 production 验收、版本更新后冒烟和后续按需巡检。脚本只证明用户可沿页面完成操作、关键数据能够在三个界面间流转，不评价 AI 回答质量、页面视觉细节或 CRM 业务效果。

以下能力继续由已经合并的 unit / contract / integration / E2E 证明，不在 production 脚本中重复故障注入：

- 询盘 idempotency replay、重复 Lead / 飞书通知抑制；
- AI / 知识不可用、高风险话题、恢复路径和零伪造回答；
- Auth / RBAC、Jobs 幂等、飞书重试和通知去重；
- EN / AR 细粒度字段映射、RTL、错误提示和非阻断视觉边界。

首次 production 验收的结论由“本脚本 live 证据 + 当前 `main` 自动化证据”共同组成。脚本通过不代表所有异常路径已在 production 重放。

## 2. 决策：单入口、全浏览器执行

### 2.1 一个脚本入口

首版仅增加一个入口：

```text
scripts/smoke/live-workflow-smoke.ts
```

所有编排、浏览器上下文、证据采集和清理都从该入口启动。若后续文件明显超过可维护规模，可以只把内部 helper 拆文件，但对外仍保持一个命令和一套流程，不复制 acceptance / routine 两套实现。

### 2.2 三个隔离的浏览器上下文

```text
live-workflow-smoke.ts
  ├─ Visitor Context：匿名访问官网、提交询盘、使用 ChatWidget
  ├─ Portal Context：登录 /dashboard、查看 Lead、接管、回复、解决
  └─ Feishu Context：打开公开多维表格、搜索并核对合成记录
```

- Visitor Context 不复用 Portal Cookie，保持真实匿名访客状态；
- Portal Context 每轮都通过 `/dashboard/login` 输入专属测试账号，不依赖历史登录态；
- Feishu Context 直接打开公开链接，不保存飞书 Cookie，不使用 OpenAPI 或应用凭据；
- 三个 Context 不共享 cookie、localStorage、sessionStorage 或可写浏览器 profile。

### 2.3 浏览器操作与只读网络观察

所有业务写操作必须通过用户可见页面完成。脚本不得使用 `request.post()`、`fetch()` 或 Feishu OpenAPI 代替表单提交、Portal 接管、回复、解决或飞书读回。

允许只读监听由页面自身发出的网络响应，以取得 `requestId`、`sessionId` 和响应状态，便于把官网、Portal 与飞书证据关联起来。监听不得修改请求、伪造响应或绕过页面交互。

## 3. 固定前置条件

### 3.1 Portal 专属测试账号

后续创建一个 production 专属浏览器巡检账号，用于：

- 登录 `https://ivybm.com/dashboard/conversations`；
- 查看并接管合成会话；
- 发送人工回复并解决会话；
- 在 `/dashboard/leads` 读回合成 Lead。

账号要求：

- 使用独立邮箱和强随机密码，不复用真实运营人员账号；
- 初始使用满足会话接管与 Lead 只读能力的最小角色；若实际权限不足，停止并 Review，不直接扩大为全权限管理员；
- 凭据仅放在受控本地环境或 secret store，不写入本文件、`.env.example`、截图、日志或 Git；
- 每次脚本执行都重新走 Portal 登录页；账号锁定、密码过期或权限变化时返回 `BLOCKED_PORTAL_AUTH`，不伪报业务链路失败。

本方案修订阶段不创建账号、不登录 production；账号创建属于后续明确执行步骤。

### 3.2 飞书公开多维表格

测试阶段使用以下公开视图：

[飞书测试多维表格](https://my.feishu.cn/base/FWqIbgJXVaR4lus7xcScgTblnle?table=tblrmOcSYnilLCIq&view=vewdQVJ7UZ)

脚本通过 Feishu Context 打开页面并按本轮唯一邮箱 / 公司名搜索。实现前必须先确认该公开视图在无登录 Chromium 中：

- 可加载目标表格；
- 可使用页面搜索 / 筛选定位唯一记录；
- 合成邮箱或公司字段对公开访问者可见。

若公开链接要求登录、出现验证码、搜索不可用或字段不可见，返回 `BLOCKED_FEISHU_UI`。不得自动扫码、绕过验证码或回退 OpenAPI；是否改用其他验证方式由负责人另行决定。

公开链接当前只作为**读回证据**。在没有明确确认页面写权限和唯一记录定位前，不自动删除飞书记录。

### 3.3 production 执行批准

- production 首次验收仍需 jueyunai 明确批准时间窗、执行人和停止条件；
- 后续巡检需单独确认频率与执行机器，不因脚本存在自动获得 production 执行授权；
- 当前 CI 架构冻结，不在本批新增或修改 `.github/workflows/**`、`scripts/ci/**` 或 GitHub 定时任务。

## 4. 合成数据与运行身份

每轮生成一个不可复用的 `runId`：

```text
canary-YYYYMMDD-HHmmss-<6-char-random>
```

所有合成数据必须包含该标识：

```text
Name: Canary Buyer <runId>
Email: canary-<runId>@example.invalid
Company: Canary Facade <runId>
Message: [CANARY <runId>] Automated workflow smoke. No follow-up required.
Operator reply: [CANARY <runId>] Test operator reply.
```

要求：

- 只使用保留域 `example.invalid`，不向真实邮箱发送消息；
- 不使用真实客户姓名、电话、公司、询盘、合同或素材；
- Portal、飞书和报告都能通过 `runId` 精确识别本轮记录；
- production 不自动重跑失败步骤，避免重复 Lead 和不可撤回通知。

## 5. P0-A：官网询盘 → Lead → 飞书

### 5.1 浏览器操作

1. Visitor Context 打开 `/{locale}/contact`；
2. 填写姓名、邮箱、公司、**国家 / 地区**和询盘消息；
3. 点击页面提交按钮；
4. 同时等待页面自身的 `/api/inquiries` 响应与 DOM 成功提示；
5. 记录响应中的 `requestId`，但不由脚本主动调用该 API。

首次 production 验收使用 `en,ar`；后续快速巡检默认 `en`，可通过参数改为 `en,ar`。两种执行走同一套代码。

### 5.2 Portal 读回

1. Portal Context 通过 `/dashboard/login?returnTo=/dashboard/leads` 登录；
2. 在 `/dashboard/leads` 按合成邮箱或公司搜索；
3. 要求恰好找到一条记录；
4. 打开详情，确认姓名、邮箱、公司和 locale 与本轮输入一致；
5. 保存 Lead 页面截图和脱敏关联信息。

Portal UI 当前不展示 `requestId` 时，不通过数据库或内部 API 补读；报告保留页面 requestId、合成邮箱和 Portal Lead 可见证据作为关联链。

### 5.3 飞书网页读回

1. Feishu Context 打开固定公开视图；
2. 等待飞书异步 Worker 完成同步，最长 60 秒；
3. 使用公开页面搜索 / 筛选本轮邮箱或公司；
4. 要求唯一匹配，并确认姓名、邮箱、公司至少三个字段一致；
5. 保存只包含本轮合成记录的截图，不截取无关客户行。

### 5.4 通过条件

- 官网表单真实提交且 DOM 显示成功；
- `/dashboard/leads` 可见唯一对应 Lead；
- 飞书公开表格可见唯一对应记录；
- 三处可通过 `runId` / 邮箱 / 公司关联；
- 未出现真实客户数据泄露、重复匹配或凭据异常。

本脚本不在 production 重放相同 idempotency key；重复抑制继续引用当前 `main` 自动化证据。

## 6. P0-B：AI 客服 → 接管 → Lead → 飞书

### 6.1 访客三轮初筛

Visitor Context 打开 `/{locale}` 并展开 ChatWidget，使用与现有绿色 E2E 相同的完整资格信息：

1. 产品需求与国家；
2. 公司、项目阶段和面积；
3. 图纸、预算 / 采购计划、采购时间和合成邮箱。

每轮通过页面输入框和发送按钮操作。断言：

- 访客消息气泡可见；
- 前两轮各出现一个非空的 assistant 气泡；
- 页面存在知识来源标识，但不评价回答措辞或质量；
- 第三轮后页面进入等待人工接管状态，输入框不可继续发送。

脚本定位实际 DOM `data-author="assistant"` 或稳定的角色 / 文案，不使用不存在的 `author="ai"` 属性。

### 6.2 Portal 人工接管

1. Portal Context 登录 `/dashboard/conversations`；
2. 通过页面列表 / 搜索定位本轮会话；
3. 打开详情并点击“接管会话”；
4. 确认页面进入人工服务状态；
5. 输入带 `runId` 的固定测试回复并点击“发送回复”；
6. Visitor Context 等待该消息出现在当前聊天窗口；
7. Portal Context 点击“解决会话”，确认状态为已解决。

必须通过 Portal UI 先接管，再发送回复；不得直接调用 `operator-messages`，也不得假设发送消息会自动把状态改成 `human_active`。

访客端通过 12 秒轮询取得人工消息，因此人工回复读回最长等待 30 秒，不描述为 WebSocket / SSE 实时推送。

### 6.3 Lead 与飞书读回

1. Portal Context 打开 `/dashboard/leads`，按本轮邮箱 / 公司定位唯一 Lead；
2. 确认 Lead 为高意向且与合成会话资料一致；
3. Feishu Context 打开公开表格，最长等待 60 秒；
4. 先以本轮邮箱定位唯一可识别的行 / 记录容器，再在同一容器内确认姓名、邮箱和公司三项字段；跨行分散字段、重复记录或无法识别安全容器时失败关闭，不截图无关行；
5. 保存 Portal 会话、Portal Lead、访客人工回复和飞书记录截图。

### 6.4 通过条件

- ChatWidget 完成真实 2–3 轮初筛并出现 AI 回复；
- 页面进入等待接管，Portal 可接管、回复和解决；
- 人工回复能回到同一个访客浏览器；
- Portal Lead 与飞书记录均可见且能以合成身份关联；
- 没有 AI 在人工接管后继续自动回复。

高风险、AI 不可用与知识不可用路径不在 live 脚本中主动制造，继续引用 WEB-CHAT-02 自动化证据。

## 7. 数据收尾与诚实残留

本方案不再承诺“零脏数据残留”。生产主链路会留下 Jobs、审计记录和不可撤回的飞书通知；Conversation / Messages 也没有用户侧物理删除入口。

每轮在 `finally` 中执行以下**页面级、可确认**收尾：

1. 若会话已进入人工状态但尚未解决，Portal UI 尝试点击“解决会话”；
2. 若测试账号具备权限，Portal UI 将合成 Lead 标记为不跟进 / 不合格；不为自动删除扩大账号权限；
3. 飞书公开视图只读时不尝试删除；记录保留 `CANARY + runId`，由测试阶段负责人按需集中清理；
4. 任何清理失败记录为 `CLEANUP_FAILED`，不得覆盖原始业务失败，也不得伪报全绿。

删除或修改前必须重新核对 `runId`、邮箱和公司三项完全一致。搜索为 0 条或多于 1 条时停止写操作并保存证据，禁止批量处理或猜测目标。

## 8. 超时、重试与结果分类

### 8.1 超时

| 阶段                 |   上限 |
| -------------------- | -----: |
| 页面导航 / 登录      |  30 秒 |
| 单轮 AI 回复         |  45 秒 |
| 人工回复在访客端出现 |  30 秒 |
| Portal Lead 出现     |  30 秒 |
| 飞书记录出现         |  60 秒 |
| 单次完整运行         | 180 秒 |

不再承诺 8–15 秒或 45 秒完成整条真实链路。

### 8.2 重试

- production 默认零自动重试；
- 页面网络瞬断可在当前动作内进行一次只读等待，不重新提交表单或消息；
- `/api/inquiries` 存在同 IP 10 分钟 5 次限流，首次验收的 EN + AR 与后续失败排查必须控制总提交次数；
- 失败后由负责人先核对 Portal / 飞书是否已经产生副作用，再决定是否重新执行。

### 8.3 结果分类

- `PASS`：两条 live 主链路均通过且必要证据已保存；
- `FAIL_WEBSITE`：官网页面、表单或 ChatWidget 失败；
- `FAIL_AI`：真实 AI 未在时限内返回可见回复；
- `FAIL_PORTAL`：Lead、会话接管、回复或解决失败；
- `FAIL_FEISHU`：公开表格中未出现唯一对应记录；
- `BLOCKED_PORTAL_AUTH`：专属测试账号无法登录或权限不足；
- `BLOCKED_FEISHU_UI`：公开视图要求登录、验证码或不可检索；
- `CLEANUP_FAILED`：业务验证结束，但可执行的页面级收尾失败。

## 9. 证据与日志

每轮输出到仓库忽略的本地目录：

```text
artifacts/live-smoke/<runId>/
├── report.json
├── inquiry-website.png
├── inquiry-portal-lead.png
├── inquiry-feishu.png
├── chat-visitor.png
├── chat-portal-conversation.png
├── chat-portal-lead.png
└── chat-feishu.png
```

`report.json` 仅保存：

- runId、target host、locale、开始 / 结束时间；
- 每个阶段的 PASS / FAIL / BLOCKED 与耗时；
- 脱敏 requestId / sessionId / Lead 可见标识；
- 截图相对路径与清理结果。

不得保存 Portal 密码、Cookie、Authorization header、浏览器 storageState、真实客户行或完整 production 响应体。

- `--evidence=full`：成功路径保存上表全部 7 张阶段截图，用于首次 production 验收。
- `--evidence=compact`：成功路径省略官网询盘页和访客 ChatWidget 两张中间截图，只保留 Portal 会话、Portal Lead 与飞书唯一记录等最终链路证据；任一阶段失败时仍保存该失败页面截图，不能为精简证据牺牲排障信息。
- 失败截图仅在文件实际写入后登记到报告；`requestId` / `sessionId` 在 `report.json` 与控制台摘要中只保留稳定末 6 位。运行结束后，脚本通过 Portal Lead 编辑页面按 runId / 邮箱 / 公司重新确认并标记“不合格”；账号无编辑权限记为 `SKIPPED`，不唯一或收尾异常记为 `FAILED`。

## 10. 配置与命令

### 10.1 必需环境变量

```bash
SMOKE_TARGET_URL="https://ivybm.com"
SMOKE_CONFIRM_PRODUCTION="ivybm.com"
SMOKE_PORTAL_EMAIL="<dedicated smoke account>"
SMOKE_PORTAL_PASSWORD="<secret>"
SMOKE_FEISHU_TABLE_URL="https://my.feishu.cn/base/FWqIbgJXVaR4lus7xcScgTblnle?table=tblrmOcSYnilLCIq&view=vewdQVJ7UZ"
```

- `SMOKE_TARGET_URL` 必须显式提供，不默认指向 production；
- 目标 host 为 `ivybm.com` 时，`SMOKE_CONFIRM_PRODUCTION` 必须精确匹配，否则启动前退出；
- Portal 账号密码只能来自运行环境，不允许写入脚本、文档或 package 命令；
- 飞书公开 URL 不是凭据，但保持为环境变量以便测试视图变化时不改代码。

### 10.2 单入口命令

```bash
# 首次 production 验收：同一脚本运行 EN + AR，保存完整证据
pnpm smoke:live -- --locales=en,ar --evidence=full

# 后续快速巡检：同一脚本运行 EN，保存精简证据
pnpm smoke:live -- --locales=en --evidence=compact

# 本地验证：仍使用同一脚本，但必须显式传本地目标
SMOKE_TARGET_URL="http://localhost:3000" pnpm smoke:live -- --locales=en
```

package script 只提供入口，不硬编码 production URL：

```json
{
  "scripts": {
    "smoke:live": "tsx scripts/smoke/live-workflow-smoke.ts"
  }
}
```
