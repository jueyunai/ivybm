# IVYBM 正式项目迁移设计

日期：2026-07-16

## 目标

以 `/Users/zhiyun.lee/GitHub/builder/ivybm` 为唯一正式开发目录，从 `/Users/zhiyun.lee/GitHub/demo/建材出海` 选择性复制可持续开发资产，同时将商务档案、客户原始资料、生成物和敏感配置隔离在源码仓库之外。

## 迁移方案

采用“文档基线 + 客户确认的 UI 验收基准原型 + 全新正式工程”的方式。需求、架构、接入边界等 Markdown 文档进入 `docs/`；客户提供的静态网站进入 `references/website-prototype/`，作为正式官网 UI / 交互验收基准；正式 Next.js / Payload 工程后续在仓库根目录初始化。

不直接把静态原型代码提升为生产源码，因为它没有 CMS、数据库、服务端询盘、真实多页面 SEO、权限、知识库和部署结构，而且仍使用外部占位图片与联系信息。正式工程允许替换技术实现和占位内容，但必须高保真还原原型的视觉层级、版式、色彩、字体、间距、组件状态、导航 / 轮播 / 筛选 / 表单交互、桌面 / 平板 / 移动响应式，以及英文 LTR 和阿拉伯语 RTL 效果；任何主动改版需另行获得客户确认。

## 纳管边界

纳管：一期需求、技术选型、架构图、平台接入调研、企业邮箱建议、供应商能力分析、静态网站原型。

不纳管：合同、已填写签署文件、报价 Excel / Word / PDF、客户会议原件、供应商原始 PDF、渲染预览、浏览器日志、临时文件、运行数据库、上传文件、备份及任何访问密钥。

## 后续顺序

1. 初始化 Git 并配置私有远程仓库。
2. 轮换已暴露的腾讯云 API 密钥。
3. 初始化 Next.js + Payload + PostgreSQL 正式工程。
4. 建立 Docker Compose、本地开发环境、测试和构建检查。
5. 配置 `dev.ivybm.com`、OpenResty 和 HTTPS。
6. 先完成 CMS 数据模型，再按客户确认原型高保真还原官网 UI、交互与内容结构。
