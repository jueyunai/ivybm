# 社媒 1-3 张配图发布完整闭环方案

- **状态**: 实现完成，待 Draft PR 审查与真实平台联调
- **UI Owner**: jueyunai
- **平台执行 Owner / 强制 Reviewer**: xuemusi
- **独立分支**: `feat/task-123-multi-image-publishing`

## 1. 目标

AI 内容工作台允许一次选择或拖入 1-3 张图片，并将多图草稿作为 Carousel/Multi-image 通过 Facebook、Instagram 和 LinkedIn 官方 API 发布。不得只恢复 `<input multiple>` 后让发布入口返回 409。

## 2. 产品与数据契约

```typescript
export const CONTENT_STUDIO_MIN_ASSET_COUNT = 1
export const CONTENT_STUDIO_MAX_ASSET_COUNT = 3

export type MultiImageExecutionRoute =
  | 'facebook-photos-multi'
  | 'instagram-carousel-staged'
  | 'linkedin-multi-image-staged'
```

- 1 张图片使用现有单图 route；2-3 张使用对应平台多图 route。
- 上传文件继续默认 `isPublic=false`，仅在人工审核通过并创建发布任务时提升为受控公开资产。
- `GeneratedContents.assets` 保持 `hasMany`；`contentType` 在 2-3 张时为 `carousel`。
- 单文件仍限制 8 MiB；允许 AVIF/JPEG/PNG/WebP 入库，发布前按平台能力转换或拒绝不兼容格式，错误必须指明具体文件。

### 3.3 平台 adapter

- `[MODIFY] src/modules/platforms/meta/publishingRequests.ts`

- Facebook：逐张创建未发布 photo，再通过 `attached_media` 创建 feed post。
- Instagram：逐张创建 `is_carousel_item=true` 子容器，全部 ready 后创建 `media_type=CAROUSEL` 主容器并 publish。
- LinkedIn：逐张完成图片上传后通过 `content.multiImage.images[]` 创建 post。
- 任一步结果未知时进入 `delivery_unknown`，不得自动重复创建主贴文。

## 4. API 与幂等契约

```typescript
interface MultiImageCheckpoint {
  assetIds: Array<number | string>
  uploadedMediaIds: string[]
  childContainerIds: string[]
  parentContainerId: string | null
  publishedPostId: string | null
  completedStep: 'none' | 'assets-uploaded' | 'container-created' | 'published'
}
```

现有发布命令的 Idempotency-Key、人工审核、账号 readiness、kill switch 与多平台分别记账规则保持不变。每个平台分别成功或失败，不能把部分成功合并成单一成功状态。

## 5. 明确不做

- 不支持超过 3 张、视频、混合图视频、定时发布或无人值守发布。
- 不以人工复制粘贴代替官方 API。
- 不在缺少受控账号时声称真实平台联调通过；只能记录 fixture/contract 证据与 blocker。
- 不 push、不创建 PR、不部署 production，除非用户另行授权。
