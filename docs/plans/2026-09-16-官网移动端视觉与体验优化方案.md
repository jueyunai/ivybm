## 1. 目标、成功标准与范围取舍

### 1.1 背景

客户在手机端浏览官网时反馈体验不佳。基于 iPhone 14、iPhone SE 和 360px Android 视口核对，本批只处理直接影响客户 UAT、内容可读性和询盘转化的三个问题：

1. Capabilities 与 For Professionals 页面首屏 H1 后紧跟重复 H2/描述，移动端近两个屏幕重复表达同一信息。
2. 移动端菜单隐藏了桌面端的 Upload Drawing 核心 CTA，菜单没有遮罩、背景滚动锁定和小屏内部滚动约束。
3. ChatWidget 打开后，外部 launcher 与面板 Header 同时显示关闭按钮，在移动端重叠并遮挡正文。

### 1.2 成功标准

- 英文和阿拉伯语的 Capabilities、For Professionals 页面各只有一个页面级 H1；正文 H2 与 Hero 文案语义递进，不重复。
- 390 × 844、375 × 667、360 × 800 视口下，移动菜单中的最后一个 CTA 始终可滚动到、可点击。
- 菜单打开时背景页面不能滚动；点击遮罩、选择路由或按 Escape 均关闭菜单并恢复原有 body 样式。
- 移动菜单在 LTR/RTL 下方向、对齐和 CTA 顺序正确。
- 390px 及以下视口打开 ChatWidget 时只显示面板 Header 内一个关闭按钮；关闭后 launcher 恢复显示并获得焦点。
- 1440 × 900 桌面端不发生非预期导航、Hero、Grid 或 ChatWidget 布局回归。

### 1.3 范围取舍

本批只交付上述三个 UAT 修复。原方案中的骨架屏流光、Hero Swipe、产品 Tab Scroll Hint 和上传区移动端文案属于非阻断微交互，按当前 MVP Scope Freeze 后置，不占用本批工期。

“桌面端零回退”定义为**没有非预期结构、交互或布局回归**，不再使用“0 像素差异”的绝对表述。正文 H2 文案是有意变化，允许其产生经审查的局部文本换行差异。

### 3.2 SiteHeader 移动菜单契约

保持现有七项导航顺序不变。桌面 `.nav-quote` 和 WhatsApp 图标保持原状；仅在 `.mobile-navigation` 底部新增：

1. 主 CTA：`copy.actions.uploadDrawing`，链接 `localePath(locale, '/contact')`，使用现有 `IconUpload`。
2. 可选 WhatsApp CTA：仅当 `whatsappHref` 存在时渲染，继续使用当前 URL 规范化结果，不增加 API、Webhook 或 SDK。

菜单按钮与抽屉必须建立以下关联：

```tsx
<button
  aria-controls="mobile-navigation-drawer"
  aria-expanded={menuOpen}
  ref={menuButtonRef}
/>

<nav
  aria-label={copy.accessibility.mobileNavigation}
  data-open={menuOpen}
  id="mobile-navigation-drawer"
/>

<header className="site-header" data-menu-open={menuOpen}>
  {/* utility strip、nav shell、backdrop 与 mobile navigation */}
</header>
```

交互契约：

- 打开菜单时保存 `document.body.style.overflow` 原值并设置为 `hidden`。
- 关闭、组件卸载和路由跳转时恢复原值，禁止永久锁死页面。
- Escape 关闭菜单并将焦点归还 `menuButtonRef`。
- 定义统一的 `closeMobileMenu()`，同时执行 `setMenuOpen(false)` 与 `setLangOpen(false)`；点击遮罩和任一菜单链接必须复用该函数，禁止只关闭其中一个浮层。
- 打开移动菜单前先关闭语言下拉；打开语言下拉前先关闭移动菜单，保证两层浮层互斥，不出现语言气泡悬留。
- `pathname` 变化时必须调用 `closeMobileMenu()`；浏览器后退、前进或系统侧滑返回不能依赖 Link 的 `onClick` 做清理。
- 遮罩仅处理指针关闭行为并设置 `aria-hidden="true"`；键盘用户通过菜单按钮或 Escape 获得等价关闭路径。
- 不修改当前 `.mobile-navigation` 的 `position: absolute` 与 `top: calc(100% + 8px)` 定位契约。

统一关闭与互斥切换的最低实现契约：

```ts
const closeMobileMenu = useCallback((): void => {
  setMenuOpen(false)
  setLangOpen(false)
}, [])

const toggleMobileMenu = (): void => {
  setLangOpen(false)
  setMenuOpen((open) => !open)
}

useEffect(() => {
  closeMobileMenu()
}, [closeMobileMenu, pathname])
```

实现时在现有 React import 中加入 `useCallback`。语言菜单触发器从关闭切换为打开时必须先执行 `setMenuOpen(false)`；Escape 路径在调用 `closeMobileMenu()` 后将焦点归还 `menuButtonRef`。

小屏层叠、遮罩和可达性 CSS 契约：

```css
@media (max-width: 1100px) {
  .site-header[data-menu-open='true'] {
    z-index: 70;
    backdrop-filter: none;
  }

  .site-header[data-menu-open='true'] .nav-shell {
    position: relative;
    z-index: 2;
  }

  .mobile-navigation {
    z-index: 3;
    max-height: calc(100vh - 100% - 18px - env(safe-area-inset-bottom, 0px));
    max-height: calc(100dvh - 100% - 18px - env(safe-area-inset-bottom, 0px));
    overflow-y: auto;
    overscroll-behavior: contain;
    -webkit-overflow-scrolling: touch;
  }

  .mobile-nav-backdrop {
    position: fixed;
    inset: 0;
    z-index: 1;
    touch-action: none;
    user-select: none;
    -webkit-user-select: none;
  }
}
```

- 当前 `.site-header` 的 `backdrop-filter: blur(12px)` 会使内部 fixed backdrop 以 Header 为包含块。菜单打开时必须通过 `data-menu-open='true'` 临时将其设为 `none`，否则遮罩只覆盖 Header 高度。
- Header 本身必须在菜单打开时提升至 `z-index: 70`，高于根层 `.chat-widget { z-index: 60; }`；仅提高子级 drawer 的 z-index 无效。
- Header 内部固定使用 backdrop `1`、nav shell `2`、mobile navigation `3` 三层，防止遮罩挡住菜单按钮或抽屉。
- 高度公式中的 `100%` 表示当前 Header 实际高度，`18px` 包含既有 8px 顶部间距与至少 10px 底部留白；禁止改回固定减去 96px/144px 的魔法数字。
- `100vh` 必须位于 `100dvh` 之前：不支持动态视口单位的旧版 WebKit 使用前者，支持 `dvh` 的浏览器由后者覆盖。
- `touch-action: none` 只加在 backdrop，不得加到 `.mobile-navigation`，以免破坏抽屉内部滚动。

RTL 不使用硬编码左右定位；新增 CTA 的图标、间距和对齐使用逻辑属性，或提供明确的 `html[dir='rtl']` 对称规则。

## 6. 已知坑与防护

1. **H1/H2 共用字段**：不得直接修改现有 `title/subtitle`；正文必须读取新字段。
2. **CMS 回退**：PageHero 继续保持 `page?.title || copy.*.title` 和 `page?.summary || copy.*.subtitle`。
3. **导航定位单测**：现有测试要求 `.mobile-navigation` 保持 `position: absolute` 和相对 Header 的 `top: calc(100% + 8px)`。
4. **小屏 CTA 截断**：body 锁定前必须保证菜单自身可滚动，375 × 667 是硬性验收视口。
5. **滚动锁泄漏**：Effect cleanup 必须恢复修改前的 body inline style，而不是无条件写空字符串。
6. **焦点恢复**：ChatWidget launcher 仅用 CSS 隐藏，不从 DOM 卸载；关闭后现有 `launcherRef.current?.focus()` 必须继续通过测试。
7. **RTL**：EN/AR 文案、CTA href、图标间距和抽屉对齐必须双向验证。
8. **测试完整性**：因文案和 DOM 结构变化而失败的测试应正向更新精确断言，不得删除、弱化或 skip。
9. **视口高度兼容**：`100vh` fallback 必须先于 `100dvh`；测试至少读取最终计算值并在 375 × 667 视口证明最后一个 CTA 可达。
10. **浮层状态收敛**：移动菜单与语言下拉必须互斥；backdrop、Escape、菜单链接和路由跳转不得留下任一浮层状态。
11. **Worktree 保全**：当前临时 worktree 含未提交文档，禁止直接 remove、文件系统强删或用 reset/checkout 清理；迁移前必须 stash（含 untracked）并核对可恢复性。
12. **Fixed 包含块**：Header 菜单打开时必须关闭 `backdrop-filter`，并以 E2E 断言 backdrop 的 bounding box 覆盖完整 viewport。
13. **根层叠顺序**：菜单打开时 Header 必须高于 ChatWidget；测试用 `document.elementFromPoint()` 或可见性断言确认客服 launcher 不在菜单/遮罩之上。
14. **历史导航清理**：覆盖 `pathname` 变化，不允许后退、前进或侧滑返回后保留菜单、语言下拉或 body scroll lock。
