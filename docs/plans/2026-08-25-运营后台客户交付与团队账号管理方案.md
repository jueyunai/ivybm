# IVYBM 运营后台客户交付与团队账号管理方案

> 文档状态：已实施，待 Draft PR 审查
>
> 范围决策：采用方案 B，在 `/dashboard/settings` 交付个人改密与管理员团队账号增删改查；不要求成员首次登录强制修改密码。
>
> Owner：`jueyunai`；涉及 Auth/RBAC、`users` 和 Session 安全边界，合并前必须由 `xuemusi` 独立 Review。

## 1. 目标与范围

本方案用于补齐 IVYBM 新版运营后台（`/dashboard`）面向客户团队独立交付时的账号管理能力，并把客户实际操作、服务端权限和上线验收统一到同一套规则中。

继续遵守当前 MVP 冲刺基线：

- `/dashboard` 是客户运营、培训和验收的唯一后台；Payload `/admin` 只保留给受限内部维护人员；
- 不重建认证系统，复用 Payload Auth、现有 `users` Collection、Session、三角色 RBAC 和审计 Hook；
- 团队账号管理属于新增的客户交付能力，预计 1.5–2 个工作日；按“一人同时最多一个功能 PR”执行，当前功能 PR 未结束前不并行创建第二个功能 PR；
- 四条 MVP 真实闭环仍高于账号管理；账号管理不得扩大为多租户、组织架构、复杂审批或完整 CRM。

### 1.1 本期交付范围

1. 所有登录用户可在 `/dashboard/settings` 修改自己的密码；
2. `admin` 可查看团队成员列表；
3. `admin` 可创建 `admin`、`operator`、`sales` 账号；
4. `admin` 可修改成员邮箱和角色；
5. `admin` 可锁定、解锁成员账号；
6. `admin` 可直接为成员设置新密码；
7. `admin` 可删除满足安全条件的成员账号；
8. 所有写操作具备服务端鉴权、输入白名单、幂等、并发保护、Session 撤销和审计证据。

### 1.2 明确不做

- 不要求新成员首次登录强制改密；
- 不建设邮件邀请、一次性邀请链接或邮件找回密码；
- 不建设 MFA、SSO、SCIM、部门层级、权限自定义或批量导入；
- 不新增租户、企业或团队数据模型；
- 不新增“上次登录时间”字段，也不为展示该信息额外扫描审计日志；
- 不允许客户使用 `/admin` 管理账号。

## 2. 客户自主运营闭环

```text
官网英文/阿语询盘 ────────────────┐
                                   ├─> Lead ─> 飞书客户表 ─> 飞书通知/销售跟进
官网 AI 对话 ─> 人工接管 ─> Lead ─┘

/dashboard/website-content
  ─> 保存/发布
  ─> Next.js 按需缓存重验证
  ─> Cloudflare 定向清理（对应 PR 合并且生产配置启用后）
  ─> 英文/阿语公开官网

/dashboard/content-studio
  ─> AI 生成 ─> 人工审核 ─> 用户点击发布
  ─> Facebook / Instagram / LinkedIn 官方 API
  ─> 各平台独立结果、内容 ID / URL
```

### 2.1 P0-A：官网询盘到飞书

- 官网表单和满足建档条件的会话询盘写入 `Leads`；
- `Leads` 向飞书客户表执行单向推送，不承诺飞书到 Portal 的反向同步；
- 管理员通过 `/dashboard/leads` 扫码连接飞书并创建客户表；
- 飞书新增记录通知由客户管理员在飞书自动化中配置，验收时必须实际确认群消息或指定成员提醒到达。

### 2.2 P0-B：AI 客服到人工跟进

- 官网 AI 完成 2–3 轮初筛；
- 高风险问题或客户明确要求人工时进入 `handoff_requested`；
- 运营或已分配业务员在 `/dashboard/conversations` 接管并回复；
- 需要销售跟进的会话必须生成或关联 Lead，并进入飞书同步链路。

### 2.3 P0-C：Portal CMS 到公开官网

- 运营人员在 `/dashboard/website-content` 编辑产品、案例、文章和页面；
- 发布后先触发 Next.js `revalidatePath`；
- Cloudflare 缓存清理只有在 `fix/cloudflare-cache-purge` 对应 PR 合并、部署且生产变量启用后才视为可用；
- 验收同时核对 CMS 记录、公开页面内容和缓存命中后的最新版本。

### 2.4 P0-D：AI 内容到三平台发布

- 用户必须在内容工作台完成审核并明确点击“立即发布”；
- 服务端调用 Facebook、Instagram、LinkedIn 官方 API；
- 每个平台独立记录成功、失败或 `delivery_unknown`，结果未知时停止自动重发；
- 外部权限不足的平台保持 `conditional` 或 `blocked`，不能用人工复制粘贴冒充 API 发布。

## 3. 复用的现有账号基础

当前代码已经具备以下能力，本方案不得平行重建：

- `users` 是 Payload Auth Collection；
- 角色固定为 `admin`、`operator`、`sales`，并保存到 JWT；
- 密码最少 12 个字符；
- 连续登录失败 5 次后锁定 10 分钟；
- Token 有效期 2 小时，并启用服务端 Session；
- `admin` 可管理用户，其他角色只能读取或更新自己，普通用户不能修改自己的角色；
- 用户创建、更新、删除和登录已通过 Hook 写入 `audit-logs`；
- `/dashboard/settings` 已展示当前账号邮箱和角色，可直接扩展个人改密与团队管理面板。

本期不新增 `users.status`、`lastLoginAt` 或 `mustChangePassword` 字段，因此不需要数据库 migration。

| --- | --- | --- | --- |

| 修改本人密码 | 允许 | 允许 | 允许 |
| 查看团队成员列表 | 允许 | 拒绝 | 拒绝 |
| 新增成员 | 允许 | 拒绝 | 拒绝 |
| 修改成员邮箱/角色 | 允许，受安全约束 | 拒绝 | 拒绝 |
| 重置成员密码 | 允许，受安全约束 | 拒绝 | 拒绝 |
| 锁定/解锁成员 | 允许，受安全约束 | 拒绝 | 拒绝 |
| 删除成员 | 允许，受安全约束 | 拒绝 | 拒绝 |

`sales` 对线索和会话继续沿用现有 `assignedTo` 权限；账号 CRUD 不改变业务数据的访问规则。

## 5. 页面与交互设计

### 5.1 个人账户安全

所有角色在 `/dashboard/settings#account` 看到：

- 当前登录邮箱；
- 当前角色；
- “修改密码”按钮。

修改密码表单字段：

- 当前密码；
- 新密码，12–128 个字符；
- 确认新密码。

规则：

1. 当前密码必须通过 Payload 正式登录校验，不直接读取或比对 `hash` / `salt`；
2. 新密码与确认密码必须一致，且不能与当前密码相同；
3. 密码不执行 `trim`，避免静默改变用户输入；
4. 如果 Payload 的凭据校验产生了新的验证 Session，该 Session 不得保留；
5. 修改成功后撤销该账号全部已有 Session，并跳转登录页，用户使用新密码重新登录；
6. 这是密码变更后的安全生效规则，不是首次登录强制改密；系统不保存 `mustChangePassword` 状态。

### 5.2 团队成员列表

仅 `admin` 可见。目标团队为 1–5 人，本期使用单页列表，不建设搜索、筛选和批量操作。

列表只展示安全 DTO：

- 邮箱；
- 角色；
- 创建时间；
- 状态：正常、登录失败临时锁定、管理员锁定；
- 状态到期时间（仅临时锁定时显示）；
- 操作入口。

列表接口绝不返回或透传：

- `hash`、`salt`；
- `resetPasswordToken`、`resetPasswordExpiration`；
- Session 内容；
- 初始密码或重置后的密码；
- 完整 Payload User 文档。

### 5.3 新增成员

字段：

- 登录邮箱；
- 初始密码，12–128 个字符；
- 确认初始密码；
- 角色：`admin`、`operator`、`sales`。

规则：

- 邮箱在服务端执行 `trim`、小写归一化和格式校验；
- 邮箱必须唯一；
- 初始密码由管理员直接设置，不要求成员首次登录后强制修改；
- 页面只提交密码，不在成功响应、列表、Toast、日志或审计记录中回显；
- 管理员负责通过双方认可的安全渠道把账号和初始密码交给成员。

### 5.4 编辑成员

允许修改：

- 邮箱；
- 角色。

限制：

- 管理员不能修改自己的角色；
- 不能把系统最后一个可用管理员降级；
- 邮箱变化或角色变化后撤销目标账号全部 Session，目标成员必须重新登录；
- 请求必须携带列表读取到的 `updatedAt`，如果记录已被其他管理员修改则返回冲突并刷新数据。

### 5.5 管理员重置密码

- 管理员输入并确认新密码，12–128 个字符；
- 不要求目标成员下次登录强制改密；
- 成功后撤销目标账号全部 Session；
- 新密码不回显、不记录、不进入幂等收据；
- 管理员不能通过该入口读取旧密码。

### 5.6 锁定与解锁

本期不新增业务状态字段，复用 Payload 的 `lockUntil`：

- 登录失败触发的锁定：保留 Payload 的 10 分钟锁定；
- 管理员锁定：写入固定的远期 `lockUntil`，由服务端转换成 `manually_locked` DTO；
- 解锁：清空 `lockUntil` 并把 `loginAttempts` 归零；
- `lockUntil` / `loginAttempts` 是 Payload 隐藏且禁止普通 Local API 更新的内置字段；只允许已通过 Portal 管理员鉴权、同源校验和并发检查的“锁定/解锁”命令层，用固定白名单写入执行窄范围 `overrideAccess: true`；
- 锁定时撤销目标账号全部 Session；
- 管理员不能锁定自己；
- 不能锁定系统最后一个可用管理员。

远期时间常量只存在于服务端账号模块，不暴露为客户端输入，不在多个文件重复定义。

### 5.7 删除成员

删除是不可恢复操作，页面要求管理员输入目标邮箱二次确认。

服务端必须同时满足：

1. 目标用户存在；
2. 目标不是当前登录管理员；
3. 删除后仍至少保留一个可用 `admin`；
4. 目标没有仍分配给自己的 Leads、Conversations 或 Handoffs；
5. 目标没有活动的飞书成员映射、待完成授权/注册、待执行发布任务或其他仍需要该用户身份的运行中业务引用；
6. `updatedAt` 与管理员确认时读取的版本一致。

不满足关联数据条件时返回引用类型和数量，管理员先重新分配业务数据或改用锁定；不做业务级联删除，不静默清空业务负责人。

当前数据库外键口径必须如实处理：

- `audit-logs.actor` 与 `publish-logs.actor` 使用 `ON DELETE SET NULL`，删除后仍保留历史记录；
- `generated-contents.createdBy`、`content-reviews.reviewedBy` 和 `publish-jobs.createdBy` 使用 `ON DELETE RESTRICT`，只要存在这类业务历史就禁止物理删除，管理员应改用锁定；
- `portal-command-receipts.actor` 也使用 `ON DELETE RESTRICT`；处理中收据阻止删除，已完成/已失败收据作为技术性幂等数据，在同一删除事务中先清理；
- 服务端仍捕获 PostgreSQL `23503` 作为最后一道 fail-closed 防线，统一返回 `user-has-assignments` 409，不做业务级联删。

## 6. API 与命令契约

### 6.1 路由

| 方法 | 路径 | 作用 | 权限 |
| --- | --- | --- | --- |
| `GET` | `/api/portal/settings/users` | 获取团队成员安全列表 | `admin` |
| `POST` | `/api/portal/settings/users` | 新增成员 | `admin` |
| `PATCH` | `/api/portal/settings/users/:id` | 修改邮箱或角色 | `admin` |
| `DELETE` | `/api/portal/settings/users/:id` | 删除成员 | `admin` |
| `POST` | `/api/portal/settings/users/:id/reset-password` | 管理员重置密码 | `admin` |
| `POST` | `/api/portal/settings/users/:id/lock` | 锁定成员 | `admin` |
| `POST` | `/api/portal/settings/users/:id/unlock` | 解锁成员 | `admin` |
| `POST` | `/api/portal/settings/change-password` | 修改本人密码 | 已登录用户 |

### 6.2 安全成员 DTO

```ts
type PortalTeamMemberDTO = {
  id: number | string
  email: string
  role: 'admin' | 'operator' | 'sales'
  status: 'normal' | 'security_locked' | 'manually_locked'
  lockedUntil: string | null
  createdAt: string
  updatedAt: string
}
```

服务端必须显式构造该 DTO，禁止通过对象展开返回 Payload User。

### 6.3 请求边界

- 统一使用 `readLimitedJSONObject` 限制请求体；
- 只接受 `application/json`；
- Cookie 鉴权的写请求必须校验 `Origin` / `Referer` 与正式站点同源；
- 所有写请求携带 `Idempotency-Key`，复用 Portal Command Receipt；
- 不含密码的命令继续使用现有规范化请求 SHA-256 作为收据指纹；
- 包含当前密码、初始密码或重置密码的命令，不得把密码或普通 SHA-256 密码摘要交给命令收据；先使用仅服务端可知的密钥生成 HMAC 指纹，再把 HMAC 结果和非敏感字段交给收据层，用于识别同一幂等键是否被不同请求复用；
- 密码只参与内存中的即时验证、HMAC 指纹和 Payload 写入，不写入请求日志、应用日志、审计数据或命令收据正文；
- Payload Local API 默认必须传入带 `req.user` 的 `req` 并使用 `overrideAccess: false`；仅锁定/解锁命令对 Payload 内置隐藏字段执行上述窄范围 `overrideAccess: true`；
- 不允许客户端直接写 `hash`、`salt`、`sessions`、`loginAttempts` 或 `lockUntil`；客户端只能表达“改密、重置、锁定、解锁”等业务命令。

### 6.4 并发与事务

以下检查和写入必须在同一个数据库事务内完成：

- 最后一个可用管理员保护；
- 目标账号 `updatedAt` 乐观并发校验；
- 关联 Leads / Conversations 检查；
- 用户修改、Session 撤销和命令收据完成状态。

同一个幂等键重复请求必须返回第一次已完成的安全响应；收据过期且结果不确定时，客户端先刷新成员列表，不自动重复执行删除、重置密码或锁定。

### 6.5 错误码

| HTTP | 错误码 | 场景 | 前端处理 |
| --- | --- | --- | --- |
| `400` | `invalid-input` | 邮箱、角色、密码或确认字段不合法 | 保留表单并定位字段 |
| `400` | `current-password-invalid` | 本人改密时当前密码错误 | 不说明具体认证内部信息 |
| `401` | `authentication-required` | Session 失效 | 跳转登录页 |
| `403` | `admin-required` | 非管理员访问团队管理 | 展示无权限状态 |
| `403` | `self-role-change-forbidden` | 管理员修改自己的角色 | 禁用操作并解释原因 |
| `403` | `self-reset-password-forbidden` | 管理员通过团队入口重置自己的密码 | 引导使用带当前密码校验的个人改密 |
| `403` | `self-lock-forbidden` | 管理员锁定自己 | 禁用操作并解释原因 |
| `403` | `self-delete-forbidden` | 管理员删除自己 | 禁用操作并解释原因 |
| `409` | `email-already-exists` | 邮箱已被占用 | 提示更换邮箱 |
| `409` | `last-admin-protected` | 操作会导致没有可用管理员 | 要求先新增其他管理员 |
| `409` | `user-has-assignments` | 用户仍有关联线索或会话 | 返回引用数量并要求先转交 |
| `409` | `stale-user-version` | `updatedAt` 已变化 | 刷新列表后重新确认 |
| `409` | `portal-command-result-unknown` | 幂等命令结果未知 | 刷新当前状态，禁止自动重试 |
| `404` | `user-not-found` | 目标用户不存在或已删除 | 刷新列表 |
| `503` | `user-assignment-check-failed` | 飞书成员映射等删除前引用检查无法完成 | 停止删除，改用锁定或稍后重试 |
| `503` | `team-management-disabled` | 功能开关未启用 | 展示暂不可用 |

## 8. 审计与日志

复用 `Users` Collection 现有审计 Hook：

- 新增成员记录 `create`；
- 邮箱、角色、密码、锁定和解锁记录 `update`；
- 删除成员记录 `delete`；
- 登录记录 `login`。

现有 `audit-logs` 只记录 actor、resource、documentId 和通用 action；本期不为动作子类型新增数据库字段。应用结构化日志补充无敏感信息的事件名：

- `portal.team_member.created`；
- `portal.team_member.updated`；
- `portal.team_member.password_reset`；
- `portal.team_member.locked` / `unlocked`；
- `portal.team_member.deleted`；
- `portal.account.password_changed`。

日志允许记录 actor ID、target ID、结果和错误码；禁止记录邮箱原文、密码、Token、Session 和请求 Body。

## 9. 测试与验收

### 9.1 单元测试

- DTO 只包含白名单字段；
- 邮箱、角色、密码和确认字段校验；
- 手动锁定、临时锁定和正常状态映射；
- 错误码到 HTTP 状态映射；
- 客户端不同角色的面板可见性；
- 密码不会出现在响应、错误或日志对象中。
- 密码命令收据只接收服务端 HMAC 指纹，数据库中的请求指纹不能用于离线猜测密码；

### 9.2 数据库集成测试

- `admin` 可以完成列表、新增、修改、重置、锁定、解锁和删除；
- `operator` / `sales` 不能读取团队列表或执行管理员命令；
- 所有角色都能用正确当前密码修改本人密码；错误当前密码不能改密；
- 新增与重置密码不产生明文持久化；
- 改密码、重置密码、改邮箱、改角色和锁定后旧 Session 立即失效；
- 管理员锁定后不能登录，解锁后可以登录；
- 禁止自锁、自删和修改自己的角色；
- 并发降级、锁定或删除管理员时始终至少保留一个可用管理员；
- 有关联 Leads / Conversations 的成员不能删除；
- 运行中 Handoffs、飞书授权/成员映射或发布任务仍引用成员时不能删除；生成内容、内容审核或发布任务存在业务历史时也不能删除，应改用锁定；
- 审计日志与发布日志通过 `SET NULL` 保留；已完成/失败的技术性命令收据在无其他引用时先清理，处理中收据阻止删除；
- `updatedAt` 冲突不会覆盖新数据；
- 重复幂等键不会重复创建、删除或重置；
- 同一幂等键配合不同密码请求时返回冲突，不会错误回放第一次结果；
- 每个成功动作产生对应审计记录，日志不含敏感值。

### 9.3 关键 E2E

在隔离测试数据库中验证：

1. 管理员登录并创建一个 `sales` 成员；
2. 新成员使用管理员设置的初始密码登录，无首次强制改密页面；
3. 新成员主动修改密码后被跳转到登录页，旧密码和旧 Session 均失效；
4. 管理员重置该成员密码，成员旧 Session 立即失效；
5. 管理员修改角色后，成员重新登录获得最新权限；
6. 自删、最后管理员删除、有业务关联成员删除均被正确阻止；
7. 删除无业务引用的测试成员后，该账号不能再登录。

## 10. 发布与回滚

1. 从最新 `origin/main` 创建独立功能分支；
2. 先完成后端权限与集成测试，再接入 UI；
3. Auth/RBAC、Session 和 `users` 边界由 `xuemusi` 独立 Review；
4. 合并前运行与本次 diff 直接相关的 lint、typecheck、unit、integration 和关键 E2E；
5. production 部署时先保持 `ADMIN_PORTAL_TEAM_MANAGEMENT_ENABLED=false`，验证既有登录和个人设置不受影响；
6. 在受控窗口为管理员 canary 启用团队管理开关，使用合成测试成员完成 CRUD 和 Session 失效 smoke；
7. 确认证据后保持开关启用并交付客户管理员；
8. 出现权限或账号阻断时立即关闭团队管理开关，个人改密、登录和其他 Portal 模块继续可用。

代码回滚不会恢复已经删除的用户。生产 UI 必须把锁定作为默认的可恢复处理，把删除限制为无业务引用且管理员明确二次确认的账号。

## 12. 完成定义

只有同时满足以下条件，团队账号管理才可标记为完成：

1. 客户管理员可在 `/dashboard/settings` 完成成员查询、新增、修改、锁定/解锁、重置密码和安全删除；
2. 普通成员可修改本人密码，系统不要求首次登录强制改密；
3. 非管理员无法读取团队成员列表或调用管理员接口；
4. 密码、Hash、Salt、Token 和 Session 不进入客户端 DTO、日志或审计数据；
5. 自删、自锁、最后管理员、关联业务数据和并发覆盖均被服务端阻止；
6. 密码、邮箱、角色和锁定变化后的旧 Session 立即失效；
7. 审计记录、结构化日志、定向测试和 production smoke 证据齐全；
8. `xuemusi` 完成 Auth/RBAC 独立 Review，`jueyunai` 完成 production 审批和客户交付确认。
