# 单一 production 部署手册

## 范围与边界

当前项目只有一个线上 production 环境：本地测试和 GitHub CI 是发布前质量门禁，1Panel 只负责手动拉取已发布的镜像并重建容器。本流程不使用常驻 staging、不允许服务器现场构建，也不在当前开发阶段配置自动备份。

无备份阶段禁止不可逆 migration，也不能将不可替代的客户数据写入生产数据库。应用镜像回滚不等于数据库回滚。**首次接收不可替代客户数据前，停止发布并先完成外部备份和恢复演练。**

## 发布前准备

1. 将经过 review 的提交合并到 `main`，确认 `CI` workflow 成功。
2. `Publish production images` workflow 会为该提交推送两份 SHA 标签镜像：
   - `ghcr.io/jueyunai/ivybm-runtime:<commit-sha>`
   - `ghcr.io/jueyunai/ivybm-worker:<commit-sha>`
   - workflow summary 会同时输出该 tag 对应的 runtime / worker **digest**。生产 `.env` 必须保存同一行输出中的 tag 和 digest；Compose 会用 `:<commit-sha>@sha256:…` 拉取，digest 才是实际不可变的发布引用。
3. 确认 GHCR package 保持 private，并在 1Panel 的部署端保存一个只带 `read:packages` 权限的拉取凭据。不要把该凭据写入仓库、GitHub Actions 日志或 Compose 文件。
4. 将经 review 的 `compose.yaml`、`compose.prod.yaml`、`docker/postgres/`、`scripts/preflight-production.sh` 和 `scripts/smoke-test.sh` 放入 1Panel 管理的部署目录，例如 `/opt/ivybm/`；这些文件来自已验证的提交，服务器不 clone、安装依赖或构建业务源码。

## DNS 与 1Panel 安全配置

在实际首次上线前，由域名管理员在阿里云添加以下记录，目标均为 `43.165.0.83`：

| 主机记录 | 类型  | 记录值        | 用途                     |
| -------- | ----- | ------------- | ------------------------ |
| `@`      | A     | `43.165.0.83` | 正式主站                 |
| `www`    | CNAME | `ivybm.com`   | 主站别名与 301 canonical |
| `panel`  | A     | `43.165.0.83` | 1Panel 管理入口          |

随后在 1Panel 中：

1. 为 `ivybm.com` / `www.ivybm.com` 配置 OpenResty 反向代理和 HTTPS，只转发到 `127.0.0.1:3000`。
2. 将面板绑定为 `panel.ivybm.com`，开启面板 TLS、安全入口和两步验证。面板继续使用独立端口（当前为 `8090`），不能占用 OpenResty 的 `443`。
3. 腾讯云防火墙只公开 `80` / `443`；当前面板端口只允许 `199.83.211.101`；删除公网 `22` 规则。域名绑定不能替代 IP 白名单。
4. 服务器控制通过腾讯云 Lighthouse MCP 完成，不需要开放 SSH。

## production 环境文件

在部署目录以 `.env.production.example` 为模板创建仅限服务器读取的 `.env`（推荐权限 `0600`）。只填写变量值，不要把 `.env` 提交到 Git：

```text
IMAGE_TAG
RUNTIME_IMAGE
RUNTIME_IMAGE_DIGEST
WORKER_IMAGE
WORKER_IMAGE_DIGEST
POSTGRES_DB
POSTGRES_USER
POSTGRES_PASSWORD
DATABASE_URL
PAYLOAD_SECRET
NEXT_PUBLIC_SERVER_URL
APP_VERSION
AI_PROVIDER_BASE_URL
AI_PROVIDER_API_KEY
AI_TEXT_MODEL
AI_EMBEDDING_MODEL
AI_TEXT_TIMEOUT_MS
AI_EMBEDDING_TIMEOUT_MS
AI_REASONING_ENABLED
AI_REASONING_EFFORT
TRUST_PROXY_HEADERS
APP_PORT
```

`IMAGE_TAG` 和 `APP_VERSION` 必须同为本次发布的 40 字符 Git commit SHA；`RUNTIME_IMAGE_DIGEST` / `WORKER_IMAGE_DIGEST` 必须是该 SHA 在 workflow summary 中输出的 `sha256:` digest。`DATABASE_URL` 在 Compose 网络内必须使用 `db:5432`，不能使用宿主机 `127.0.0.1`。`NEXT_PUBLIC_SERVER_URL` 是在 CI 构建阶段写入 SEO、sitemap 和 robots 的正式 HTTPS 域名，必须是 `https://ivybm.com`。

`POSTGRES_PASSWORD` 至少 24 个字符，`PAYLOAD_SECRET` 至少 32 个字符。`TRUST_PROXY_HEADERS=true` 的前提是 OpenResty 是唯一应用入口，且会覆盖客户可伪造的转发 IP 头。禁止在 production `.env` 中添加 `SEED_ADMIN_EMAIL` 或 `SEED_ADMIN_PASSWORD`，也不要执行 demo seed。

AI 服务使用通用 OpenAI-compatible HTTP 协议：`AI_PROVIDER_BASE_URL` 填写包含 API 版本前缀的端点（例如 `https://api.openai.com/v1`），`AI_TEXT_MODEL` 和 `AI_EMBEDDING_MODEL` 分别填写供应商实际提供的文本与向量模型 ID。`AI_REASONING_ENABLED` 默认 `false`；设为 `true` 时，文本请求会按 OpenAI Responses 结构额外发送 `{"reasoning":{"effort":"…"}}`。`AI_REASONING_EFFORT` 默认 `medium`，可填 `none`、`minimal`、`low`、`medium`、`high`、`xhigh` 或 `max`，但具体模型可能只支持其中一部分。若供应商不支持该标准字段，请保持开关为 `false`；不要改成供应商私有的 `thinking` 参数。向量请求不会携带 reasoning。

## 1Panel 手动发布

在 1Panel Compose 页面选择当前部署目录的 Compose 文件，并使用生产 `.env`。每次发布按以下顺序执行；命令行示例可通过 1Panel 终端或 Lighthouse MCP 执行：

```bash
./scripts/preflight-production.sh .env
docker compose --env-file .env -f compose.yaml -f compose.prod.yaml config --quiet
docker compose --env-file .env -f compose.yaml -f compose.prod.yaml pull
docker compose --env-file .env -f compose.yaml -f compose.prod.yaml up -d db
docker compose --env-file .env -f compose.yaml -f compose.prod.yaml up --exit-code-from migrate migrate
docker compose --env-file .env -f compose.yaml -f compose.prod.yaml up -d --wait --wait-timeout 120 app worker
./scripts/smoke-test.sh https://ivybm.com
```

`preflight-production.sh` 只校验格式并且不会打印 `.env` 值；`config --quiet` 只验证 Compose，不会将插值后的 secret 输出到终端。`--exit-code-from migrate` 会把 migration 失败作为发布失败返回；`--wait` 会等待 app / worker 健康后才进入 smoke test，smoke test 还会为冷启动重试 30 次、间隔 3 秒。

每次发布要一起变更 `IMAGE_TAG`、`APP_VERSION`、runtime digest 和 worker digest，直接从同一次 workflow summary 复制。不要只写 Git SHA tag：tag 可被覆盖，digest 才锁定实际镜像。不要执行 `docker compose down --volumes`，也不要让 1Panel 选择“重新构建镜像”。生产 Compose 的 `app` 只监听 `127.0.0.1`，PostgreSQL 和 worker 没有宿主机端口。

## 验证与回滚

发布成功至少满足：

- 1Panel 显示 `db`、`app`、`worker` 健康；`migrate` 一次性成功退出；
- `https://ivybm.com/api/health/live` 与 `/api/health/ready` 返回 200；
- `https://ivybm.com/en` 与 `/ar` 返回 200；
- OpenResty 是唯一公网应用入口。

如应用异常，保留当前和上一版本完整的 tag + digest 对。将 `.env` 同时改回上一版本的 `IMAGE_TAG`、`APP_VERSION`、runtime digest 和 worker digest，依次重新执行 preflight、`pull`、migration 命令、`up -d --wait` 和 smoke test。不得运行 migration down；无备份阶段不能把镜像回滚误认为数据库回滚。

GitHub 免费私有仓库当前没有服务端 branch protection；CI 成功表示该提交通过既定门禁，不代替受限写权限、PR review 与本地 pre-push hook。
