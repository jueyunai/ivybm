# 一期平台账号接入运行手册

适用范围：Task 13 的 Facebook、Instagram、TikTok、LinkedIn 条件接入。没有任何真实账号时也可保留本手册和后台配置结构；不得用假账号、假 Token 或客户密码替代。

## 当前后台能力

`/admin/collections/platform-accounts` 仅管理员可访问。每条记录可先保存为“未开始”，后续再补外部账号 ID、App ID、授权状态和能力审核状态。

- access token 与 refresh token 是只写字段，以 `PLATFORM_CREDENTIAL_ENCRYPTION_KEY` 加密；后台、REST、GraphQL、审计日志和 readiness 接口均不回显。
- `GET /api/platforms/readiness` 仅管理员可调用，返回不含令牌的配置缺口与代码/平台阻塞原因。
- 这只表示“系统已准备接入”，不表示平台已经 `available`。

## 账号到手后的最短路径

1. 在服务器 `.env` 设置独立的 `PLATFORM_CREDENTIAL_ENCRYPTION_KEY`，运行 production preflight 并发布 app / worker；不要把该值发到聊天工具。
2. 由客户保留资产 Owner 和至少两名长期管理员；客户只授予可撤销的人员、开发者或合作伙伴权限，不提供密码。
3. 在“平台账号”创建对应记录，填写真实的外部账号 ID 和非敏感 App ID；Token 只在受保护后台录入。
4. 以管理员身份请求 `/api/platforms/readiness`，按返回的 `missing` 完成环境和账号配置。
5. 仅在 production 受控窗口完成签名、OAuth/授权、Webhook 或测试发布后，才把 PoC 状态改为 `available`。

`missing=credential_decryption` 表示数据库中已有令牌，但当前 app / worker 无法用
`PLATFORM_CREDENTIAL_ENCRYPTION_KEY` 验证它；它不会把令牌回显。恢复原来的密钥，或先将账号
设为非连接状态、撤销旧令牌并重新授权录入。不要仅凭 `accessTokenConfigured=true` 把账号标为可用。

| 账号类型 | 一期用途 | 现在的真实状态 |
| --- | --- | --- |
| `facebook-page` | Messenger 入站、Facebook 图文 | 入站 route 已实现；图文发布等待 Task 12 发布任务结构与 Meta 授权 |
| `instagram-professional` | Instagram DM、Instagram 图文 | 独立的 Instagram Login OAuth 路径已实现；真实授权仍待客户提供 Instagram Professional 账号并完成 App Review；图文发布等待 Task 12 |
| `tiktok-business` | TikTok 私信 | 内部会话 / Job 存储路径已准备；缺官方通用 DM schema / 资格时 raw connector 仍必须保持 `blocked` |
| `linkedin-member` | LinkedIn 个人图文 | 可保存 OAuth 接入资料；自动发布等待 Task 12 与 LinkedIn scope 验证 |
| `linkedin-organization` | LinkedIn 企业主页图文 | 需 Company Page 合格管理员与审核；未通过时继续使用人工发布导出 |

## Meta OAuth 与 Webhook

Meta App 需要在 **Facebook Login for Business** 中建立配置，并把下列精确回调加入允许列表：

```text
https://ivybm.com/api/platforms/meta/oauth/callback
```

本地开发回调为：

```text
http://localhost:3000/api/platforms/meta/oauth/callback
```

OAuth 配置使用：

```text
META_APP_ID
META_LOGIN_CONFIG_ID
META_OAUTH_REDIRECT_URI
META_WEBHOOK_APP_SECRET
```

`META_WEBHOOK_APP_SECRET` 是同一个 Meta App 的服务器端 App Secret，同时用于 OAuth Token 交换和 Webhook 签名验证。它只注入 app，不进入 worker、migrate、CMS、日志或浏览器。启用 OAuth 时还必须配置 `PLATFORM_CREDENTIAL_ENCRYPTION_KEY`。

当前这套 Facebook Login for Business 配置只连接 `facebook-page`。管理员需先在 PlatformAccounts 创建 Facebook Page 记录并填写真实数字 ID。OAuth state 以平台凭据主密钥加密到 10 分钟 HttpOnly Cookie；回调再次校验管理员会话、state、预登记账号类型和 ID、实际 granted permissions，以及该 Facebook Page 是否在授权人的可管理 Page 列表中。身份和权限全部通过后，Page Token 才经既有 Collection hook 加密保存。

当前 Business Login 配置必须授予：

- Facebook Page / Messenger 连接：`pages_show_list`、`pages_manage_metadata`、`pages_messaging`。

权限名仍以 Meta App Dashboard 当前 App Review 页面为准；上述三项任一缺失时回调失败关闭，不保存 Token。`pages_manage_posts` 等发布权限仍是后续 Facebook 图文自动发布的条件，但不阻塞 Messenger 入站账号连接。

Instagram Professional 不复用当前 `META_LOGIN_CONFIG_ID`，而是走下方独立 Instagram Login for Business 路径。

Facebook Page / Instagram Professional Account 的入站配置还需要 app 级环境变量同时存在：

```text
META_WEBHOOK_APP_SECRET
META_WEBHOOK_VERIFY_TOKEN
META_WEBHOOK_ALLOWED_ACCOUNT_IDS
```

allowlist 必须包含对应外部账号 ID。三项任一缺失时 route 会安全返回不可用，不会连接数据库或接受未经授权的 Webhook。App Secret 与 verify token 不保存到“平台账号”记录。

Webhook callback 为：

```text
https://ivybm.com/api/webhooks/meta
```

官网同时提供 Meta App Review 可公开访问的稳定链接：`/privacy`、`/terms`、`/data-deletion`；它们跳转到默认英文页面，并提供英文 / 阿语版本。正式提交审核前仍需由客户核对法定主体、联系邮箱和政策文本。

## Instagram OAuth 与 App ID

Instagram 使用独立的 Instagram Login for Business 产品，与 Facebook 的 Business Login 配置分开：

- 在 Meta App 内添加 **Instagram API** 产品，选择 **API setup with Instagram Login**，记录独立的 Instagram App ID 和 App Secret。
- 在服务器 ".env" 配置（不要把真实值发到聊天工具）：

```text
INSTAGRAM_APP_ID
INSTAGRAM_APP_SECRET
INSTAGRAM_OAUTH_REDIRECT_URI
```

- 在 Instagram 产品设置里把精确回调加入允许列表：

```text
https://ivybm.com/api/platforms/instagram/oauth/callback
```

本地开发回调为：

```text
http://localhost:3000/api/platforms/instagram/oauth/callback
```

- 管理员先在 PlatformAccounts 创建 \`instagram-professional\` 记录，填写真实 Instagram 专业账号 ID（数字）。后台详情页显示“连接 Instagram”按钮，进入官方授权页。
- OAuth state 以平台凭据主密钥加密到 10 分钟 HttpOnly Cookie；回调校验管理员会话、state、预登记账号类型和 ID，调用 Instagram Graph API 确认账号为 \`BUSINESS\` 或 \`MEDIA_CREATOR\` 且 \`id\` 与预登记 ID 严格一致。身份通过后 access token 经既有 Collection hook 加密保存。
- 当前授权请求包含 \`instagram_business_basic\`、\`instagram_business_manage_comments\`、\`instagram_business_manage_messages\`；App Secret 仅出现在服务器到 Instagram 的 POST body 和 Instagram 文档要求的 GET 查询参数中，不回显、不进入日志、不写入 CMS。

## 明确的边界

- TikTok 没有目标地区官方 Business Messaging/DM 资格和官方事件 schema 前，不创建猜测性 Webhook parser，不使用浏览器自动化绕过。
- 即使后台已保存 TikTok Business 账号，默认 worker 仍拒绝 TikTok 规范化事件；只有官方 schema、资格、connector、fixture 和跨人代码 review 全部具备后，才可由新的代码显式启用该内部投递路径。
- 已连接账号如需改为另一条 Page / Professional Account / Member / Organization ID，必须同时重新录入或清除全部已配置的 access / refresh token；系统拒绝“旧 Token + 新外部账号 ID”的保存，避免误报连接可用。
- 首条 TikTok 会话写入后，不得为了回退旧镜像而强行执行 TikTok channel migration 的 `down`；该回滚会故意失败以保护新数据，应恢复到新镜像或按备份/前向修复流程处理。
- LinkedIn、Facebook、Instagram 的真实图文发布持久化仍依赖 Task 12 的 `PublishJobs` / `PublishLogs` 合并；在此之前只能保留 capability、配置、格式化和人工发布路径。
- WhatsApp、LinkedIn 私信、TikTok 图文发布不属于一期系统接入范围。
