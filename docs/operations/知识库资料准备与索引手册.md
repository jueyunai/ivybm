# 知识库资料准备与索引手册（一期初版）

本手册用于准备 IVYBM 官网 AI 客服知识资料，并指导运营人员完成录入、审核、索引和基础验收。知识库只用于回答已经确认的业务事实；价格、交期、付款、认证承诺和质保争议等高风险问题默认由人工确认。

## 1. 首批资料准备清单

建议首批提供 5–10 份脱敏、仍然有效、允许对外使用的资料。每份资料标明负责人、版本和生效日期。

| 优先级 | 资料         | 建议内容                                                                 |
| ------ | ------------ | ------------------------------------------------------------------------ |
| P0     | 产品手册     | 产品分类、材料牌号、常用厚度、尺寸范围、表面处理、应用场景、可定制范围   |
| P0     | 技术规格     | 公差、性能指标、安装约束、检测方法、适用标准；注明“固定值”或“需工程确认” |
| P0     | FAQ          | 产品、打样、MOQ、包装、运输、图纸、报价流程等常见问答                    |
| P0     | 意向判断规则 | 哪些信息代表高意向；必须追问的国家、项目、数量、图纸、时间和联系方式     |
| P0     | 转人工规则   | 价格、交期、付款、认证、质保、投诉、合同以及无法从知识库确认的问题       |
| P1     | 销售话术     | 英文称呼、追问模板、资料收集顺序、拒答和转人工表达                       |
| P1     | 项目案例     | 可公开的国家、项目类型、产品、工艺、难点和结果；隐藏客户敏感信息         |
| P1     | 包装与物流   | 包装方式、装柜原则、常见贸易条款说明；实际运费和日期仍由人工确认         |
| P1     | 认证与检测   | 已真实取得且在有效期内的证书、检测报告、适用产品和限制条件               |
| P2     | 历史聊天样本 | 脱敏后的真实客户问法和合格回复，用于补充评测集，不直接原样对外展示       |

语言建议：英文资料优先；阿语资料可第二批补充。专业产品名、认证名和表面处理名应由业务人员统一翻译口径，不能由系统自行猜测。

## 2. 禁止提交和需要脱敏的内容

不得上传或粘贴以下内容：

- API Key、平台 token、密码、证书私钥、数据库或备份；
- 未公开客户名称、联系人、电话、邮箱、聊天原文、合同和订单；
- 未确认的价格表、内部底价、利润、供应商采购价；
- 已过期或不适用于当前产品的认证、参数和销售承诺；
- 无授权的第三方资料、图片和完整竞品文档；
- “保证交期”“保证通过认证”“最低价”等未经授权的确定性承诺。

历史对话至少替换客户姓名、公司、邮箱、电话、项目地址、合同号和金额。确需保留国家、行业或项目类型时，应确保不能反向识别客户。

## 3. 单份知识录入模板

每份资料按以下口径整理：

```text
资料标题：
资料类型：FAQ / 产品手册 / 技术规格 / 销售话术 / 项目案例 / 其他
语言：English / العربية
版本：例如 2026.07 或 v1.2
业务负责人：
生效日期：
允许官网客户使用：是 / 否
来源链接或文件：
正文：
需要转人工的例外：
下次复核日期：
```

正文建议使用明确小标题、短段落和完整单位。例如写“常用厚度为 1.5–4.0 mm，最终规格需按图纸确认”，不要只写“厚度都可以”。同一份资料不要混放相互矛盾的旧版本和新版本。

## 4. 后台状态和操作流程

1. 在 Payload 后台进入“知识库 / Knowledge Documents”，创建资料。
2. 填写来源标题、类型、版本、语言和正文；首次保存为 `draft`。
3. 业务负责人核对事实、适用范围和对外权限。
4. 将 `reviewStatus` 改为 `reviewed`。只有已审核资料可提交索引。
5. 若资料允许官网 AI 客服引用，勾选 `customerVisible`；内部销售规则不要勾选。
6. 调用受保护的索引入口：`POST /api/knowledge/documents/{文档ID}/index`。仅 admin / operator 可执行，系统返回 Job ID。
7. 在 Operations / Jobs 查看任务：`pending → processing → succeeded`。知识文档最终应显示 `indexStatus=ready`。
8. 修改正文、版本、语言、来源或对外可见性后，资料会自动退回 `draft/pending`；必须重新审核并重新索引。

一期初版先提供受保护 API 和 Jobs 状态入口。后续可以在 Payload 文档页面增加可视化“提交索引”按钮，但按钮也只能调用同一个服务端入口，不能绕过审核和权限。

## 5. 模型或供应商切换

向量供应商、端点、模型或维度发生变化后，旧向量不会与新向量混合检索。管理员应对仍在使用的 reviewed 文档逐份重新提交索引，确认全部恢复为 `ready` 后再验收问答。

不要通过修改数据库字段伪造 ready 状态。索引任务会记录稳定的向量空间指纹；旧任务发现资料或模型路由已经变化时会安全结束，不覆盖新版本。

## 6. 失败处理

| 状态                 | 处理                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| `pending`            | 等待 worker；若长期不动，检查 worker 健康和 Jobs 队列                    |
| `processing`         | 正在切片和生成向量；超长资料可能需要更久                                 |
| `failed`             | 查看对应 Job 的 `lastError`，修复资料或模型配置后人工重试                |
| Job `dead`           | 已达到最大尝试次数；管理员确认原因后使用人工重试，不要重复新建大量任务   |
| `ready` 但回答不理想 | 检查资料是否明确、语言是否匹配、问法是否进入评测集，不要直接放宽审核边界 |

模型密钥只在部署环境或 AI Management 中配置，不写入本文档、知识正文、截图、工单或 PR。

## 7. 首批验收问答模板

建议客户先准备 30–50 条英文问题，阿语再准备 15–30 条。每条样本包含：

```text
问题：
期望命中的知识资料：
必须包含的事实：
不得出现的表述：
是否必须追问：
是否必须转人工：
期望语言：
业务审核人：
```

至少覆盖产品规格、表面处理、定制范围、图纸、MOQ、包装运输、案例、认证，以及价格 / 交期 / 付款 / 质保等高风险转人工场景。验收时检查：引用来源正确、没有引用 draft 或内部资料、供应商切换后不命中旧向量、高风险问题不擅自承诺。

## 8. 甲方准备完成标准

- 首批 5–10 份资料均有标题、版本、语言、负责人和对外权限；
- 所有客户和商业敏感信息已脱敏；
- 产品参数、认证和案例由业务负责人确认仍有效；
- 英文产品名和单位口径统一；
- 已确认转人工规则和高意向判断字段；
- 已准备至少 30 条英文验收问题及期望结果；
- 指定一名知识审核负责人和一名运营录入人员。
