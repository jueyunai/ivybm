# IVYBM 运营后台（/dashboard）文案全面检查与整改清单

**审查日期**：2026-08-23
**审查目标**：全面梳理最新版运营后台 `/dashboard` 各模块中对普通运营人员不友好的**技术语言、英文混杂、底层 ID 暴露、内部研发标记**等文案，提供业务化、通俗易懂的整改方案，形成可落地的整改清单。

---

## 一、 审查背景与整改原则

作为外贸获客与社媒运营系统，`/dashboard` 的最终使用者为业务运营与销售客服人员。当前后台部分文案直接沿用了研发阶段的状态机枚举、架构术语、英文变量及底层 UUID，导致运营人员产生认知障碍与误解。

本次整改遵循以下四大原则：
1. **去技术化（业务语言优先）**：杜绝后端架构术语（如“服务端状态机”、“补偿规则”、“Kill Switch”、“Runbook”、“受控测试”等），转化为运营视角的操作指引与业务状态说明。
2. **完全中文化（消除未汉化盲区）**：彻底清除中文界面下的残留英文（如 "Website"、"Dead"、"Internal job"、"reviewed + ready"、"Auto"、"Other" 等）及英文错误提示。
3. **消除底层 ID 乱码感（语义化展示）**：会话、线索、素材及任务避免直接裸露完整的数据库 UUID 或大写枚举代码（如 `#session-e9a3c4b6...`、`FEISHU.LEAD.SYNC`），提供包含渠道、客户特征或业务类型的友好标题。
4. **剔除内部研发标记与过度安全免责**：清除暴露内部敏捷开发代号（如 "Task 11"）、开发者个人 GitHub 账号（如 `jueyunai` / `xuemusi`）以及令用户困惑的安全免责声明（如“但仍只返回安全摘要”）。

## 四、 实施路线与代码修改建议

本次整改涉及前端文案字典、组件展示逻辑和知识库错误摘要的展示契约；不新增数据库结构或 migration，但后端会继续保存稳定错误码供 Portal 本地化展示。建议按以下两批次进行快速落地：

   - 替换设置 `settings` 中的 `Payload`、`环境变量` 与 `nextSteps` 中的黑话。
2. `src/admin-portal/modules/content-studio/messages.ts`：
   - 替换 `Content Studio` 的工作标题、事实主张、MOQ 释义等。
