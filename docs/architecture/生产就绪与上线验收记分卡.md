# IVYBM 一期 MVP 生产就绪与上线验收记分卡

> **适用范围**：一期 MVP 正式向客户交付、重大版本发布与上线 UAT 终验时的阶段性审计依据。
> **使用原则**：按需使用。仅在阶段性大版本交付或客户验收时由 `jueyunai` 与 `xuemusi` 联合核对签字；日常常规修复、小改动与文案调整**不强制**每次重复打分。

---

## 一、 生产就绪分级定义

| 档位 | 定位 | 判据 |
| :--- | :--- | :--- |
| **Bronze (可演示级)** | 最低可跑通 | 核心流跑得通，错误不致命，但无完整回归保护，仅供内部 Demo，**不可商用** |
| **Silver (商业稳健级)** | **IVYBM 交付目标** | 回归率为零、前后端契约对齐、RBAC 与数据隔离完备、热点无 N+1 与超时、结构化日志与追踪齐备、具备可逆回滚预案 |
| **Gold (高加固级)** | 关键金融/交易级 | 核心路径 pass^k 可靠性加固、多区域容灾、全自动化故障注入与演练 |

**原则**：项目整体档位取决于各维度的**最低档**。IVYBM 一期上线交付的底线要求为 **全维度达到 Silver 级**。

## 三、 四条核心 MVP 闭环终验签字

在正式向客户交付前，必须在生产（或等价受控真实环境）中逐项确认以下四条核心闭环：

### [ ] P0-A: 官网询盘 $\rightarrow$ Lead $\rightarrow$ 飞书同步
- **验证场景**：英文与阿语官网提交真实询盘；
- **验收标准**：
  1. `/dashboard/leads` 产生对应 Lead 记录，国家与联系方式解析准确；
  2. 飞书多维表格新增对应记录，携带统一关联标识；
  3. 重复提交不产生重复客户。

### [ ] P0-B: 官网 AI 客服 $\rightarrow$ 人工接管 $\rightarrow$ Lead $\rightarrow$ 飞书
- **验证场景**：英文与阿语真实访客对话、询价与高风险触发；
- **验收标准**：
  1. 正常业务问答基于正式知识库准确回答；
  2. 涉及价格/认证/高意向时正确触发人工接管，状态机转为 `human_active`；
  3. 产生 Lead 并向飞书推送高意向/接管通知摘要；AI 服务中断时优雅降级。

### [ ] P0-C: Portal CMS $\rightarrow$ 公开官网实时发布
- **验证场景**：在后台新建/修改产品、案例或页面并发布；
- **验收标准**：
  1. `/dashboard` 完成内容保存与审核发布（无需进入 `/admin`）；
  2. 公开站点对应中/英/阿页面内容即时更新；
  3. Cloudflare CDN 缓存自动清除对应 URL，移动端与 RTL 显示正常。

### [ ] P0-D: AI 内容工作台 $\rightarrow$ 用户点击 $\rightarrow$ 三平台官方 API 发布
- **验证场景**：在工作台生成并人工审核图文，点击“立即发布”；
- **验收标准**：
  1. 服务端按已选平台（Facebook / Instagram / LinkedIn）分别调用官方 API；
  2. 已获权限平台返回真实平台内容 ID 与 URL，记录独立发布历史；
  3. 未获外部权限平台诚实标记 `conditional` / `blocked`，杜绝假成功。
