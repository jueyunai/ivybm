# 光年触达与易飞轮供应商能力调研分析报告

调研日期：2026-06-28  
调研对象：光年触达 iSales、易飞轮 / 乘蜂出海  
项目背景：佛山建材出海企业铝单板独立站、AI 客服、海外社媒运营、飞书 CRM 与多渠道获客系统

> 范围状态（2026-07-20）：本文为 2026-06-28 的历史供应商调研。原文中“第一阶段”“WhatsApp 入站”“Meta PoC”“TikTok P2”等建议已被当前一期范围覆盖，不应作为现行交付承诺。当前一期会话为 Facebook Messenger、Instagram DM、TikTok 私信，图文发布为 Facebook、Instagram、LinkedIn；WhatsApp 移出一期，二期再评估网页插件等替代接入；LinkedIn 私信仍仅人工辅助。供应商能力描述保留作背景参考。

## 1. 历史结论摘要

光年触达和易飞轮不是同一类供应商。

- 光年触达 iSales 更偏“AI 外贸销售 Agent”：核心在主动找客户、客户画像、联系方式补全、Email / WhatsApp 个性化触达、反馈迭代和企业模型。它适合补强主动开发客户能力，但其中“全球数据库”“WhatsApp 账号池”“自动营销触达”需要重点核实数据合规、账号归属、封号责任和客户聊天数据归属。
- 易飞轮更偏“海外社媒矩阵运营系统 + 陪跑服务”：核心在 AI 视频混剪 / 翻译、批量发布、多账号运营、评论私信统一管理、社媒陪跑、账号注册养号、短视频运营和广告投放指导。它对本项目最有参考价值的是社媒运营工作流、内容配额、陪跑交付和矩阵管理结构，但不是完整的官网 + AI 客服 + 飞书 CRM 闭环。
- 本项目更适合自研“轻量闭环版”，不要照搬两家供应商的重服务、账号池和全平台承诺。第一阶段应优先实现：铝单板独立站 + CMS、官网 AI 客服、WhatsApp 入站会话、Meta 消息 PoC、AI 内容工作台、飞书 CRM、人工审核后发布辅助。
- 不建议第一阶段承诺：LinkedIn 私信自动读取 / 批量发送、WhatsApp 公共账号池、海外平台批量养号、全网私信无差别统一接入、全自动无审核发布、供应商级全球付费联系人数据库。

### 3.2 联网资料核验

公开官网显示，iSales 主打定制化模型、全渠道获客、自动化营销和持续学习进化；其官网还提到找客户模型、客户画像定制、营销内容定制、海外 60 多家付费数据库、搜索引擎 / 海关数据 / 社交媒体 / 地图 / 展会等数据来源。

光年触达关于我们页面显示，该公司聚焦 AI 出海营销，产品以 AI Agent 为核心，强调“执行-反馈-迭代”的企业模型。公开媒体报道显示，光年触达 2026 年 3 月完成百万美元天使轮融资；2026 年 6 月报道提到新版 iSales 从主动获客延伸到 Leads、Medias、Website 三个模块，覆盖客户开发、社媒运营和官网线索承接。

判断：公开资料与 PDF 方案方向基本一致，供应商产品正在从“主动找客户”扩展到更完整的出海营销链路。但公开资料无法证明其 WhatsApp 账号池、数据库来源、联系方式补全成功率和具体交付效果，采购或对标时必须追问底层实现和数据权责。

### 3.3 能力优势

- 主动获客链路完整：从客户画像、找客户、联系方式补全到多渠道触达，逻辑闭环比单纯内容工具更强。
- 外贸垂直场景明确：产品定位面向中小外贸企业，与本项目 ToB 建材出海客户群匹配。
- 算力点计费便于解释：可以按找客户、补全、发邮件、发 WhatsApp 分拆成本，有利于客户理解 ROI。
- 反馈迭代思路值得借鉴：把点击、回复、人工判断反哺模型，适合本项目后续做客户评分和话术优化。

### 3.4 主要风险

- 数据来源风险：全球数据库和联系人信息补全不是普通自研可免费复制的能力，涉及数据授权、跨境数据、隐私合规和成本。
- WhatsApp 账号池风险：公共账号池对客户很有吸引力，但必须核实是否为官方 WhatsApp Business Platform / BSP 方案，账号归属是谁，封号后责任归谁，聊天记录和客户资产能否导出。
- 主动触达风险：Email / WhatsApp 冷启动营销可能受平台政策、退订机制、目标国家隐私规则和账号信誉影响。
- 黑盒效果风险：所谓“可开发潜在客户并营销激活”需要定义成功标准，否则容易把数据量等同于有效商机。

判断：公开资料与 PDF 方案匹配，易飞轮确实围绕海外社媒矩阵运营展开。但其官网可抓取文本较少，第三方页面信息需作为参考而非审计结论。方案中涉及批量绑定账号、账号注册养号、无需科学上网发布等能力，实际落地强依赖供应商资源、平台政策、网络环境和账号风控，不适合作为本项目自研第一阶段的强承诺。

### 4.3 能力优势

- 社媒矩阵交付完整：覆盖内容生成、视频混剪、翻译、本地化、发布、互动、数据、复盘和培训。
- 对运营服务包装成熟：按 12 个月套餐、账号数、内容条数、飞轮点、广告投放月数拆分，便于面向客户解释。
- 适合“缺运营团队”的企业：陪跑、账号定位、对标调研、脚本拆解、拍摄协助可以降低客户启动门槛。
- 对本项目社媒模块参考价值高：尤其是内容资源中心、统一互动管理、成效分析、轻量 CRM、广告线索入库。

### 4.4 主要风险

- 年费和服务包偏重：本项目当前目标是低成本跑通获客闭环，不适合直接对标 5-10 万 / 年的重运营套餐。
- 账号服务边界复杂：注册养号、手机、网络费用、IP、设备、封号恢复、账号归属都需要明确。
- 平台接口不一定全靠官方 API：方案里“无需科学上网”“API 接口稳定发布”等描述需要核实具体技术路径，不能推断自研可稳定复刻。
- 线索质量不等于内容数量：多账号、多视频、多发布只解决曝光和运营效率，不直接保证 ToB 大项目客户质量。

## 6. 平台技术边界核查

### 6.1 WhatsApp

WhatsApp Business Platform 官方按送达消息计费，计费取决于收件市场和消息类别，类别包括 marketing、utility、authentication、service。官方说明 service 消息不收费，用户从 Click-to-WhatsApp 广告或 Facebook Page CTA 发起对话后，72 小时内有 free entry point 规则。

项目判断：

- 官网 / WhatsApp 入站咨询、AI 回复、人工接管和飞书入库适合作为 P0。
- 主动营销模板、批量触达需要另算官方消息费和合规边界。
- 不建议用非官方 WhatsApp Web 逆向方案做生产级核心能力。
- 对供应商的“WhatsApp 账号池”要重点核实是否官方、账号是否归甲方、聊天记录是否可导出。

### 6.2 Facebook Page / Messenger 与 Instagram

Meta Pages API 支持以公共主页身份创建、发布、更新帖子，并需要相关 Page 权限和 Page access token。Instagram 官方也提供 Content Publishing API 和 Messaging API，但真实业务使用通常涉及专业账号、业务资产、App Review、权限审核和 Webhook 运维。

项目判断：

- Facebook Page 发帖、Instagram 内容发布、Page / IG 入站消息可以作为 P1 官方接入方向。
- 第一阶段可以先做“内容生成 + 人工审核 + 发布队列 / 一键跳转”，降低审核和风控不确定性。
- Meta 消息接入要写明“以 App Review / 权限通过为正式上线前置条件”。

### 6.3 LinkedIn

LinkedIn 官方文档显示，开放给所有开发者的权限主要是登录资料、邮箱和分享内容；大多数权限和合作项目需要 LinkedIn 显式批准。销售相关能力需要成为 Sales Navigator Application Platform 合作伙伴。

项目判断：

- LinkedIn 是客户重要获客渠道，但不适合作为 MVP 承诺自动读取私信、批量加好友或自动群发。
- 可实现“人工主导 + AI 辅助”：话术生成、客户画像整理、手动导入线索、跟进提醒、来源归因。
- 任何 RPA 自动化都必须作为实验能力，不应写进固定验收范围。

### 6.4 TikTok

TikTok API for Business 包含 Business Messaging API，可支持实时收发消息、自动回复和消息线程管理；TikTok Content Posting API 支持视频 / 图片发布，但 direct post 需要注册应用、授权 scope、目标用户授权，未审核客户端发布内容会受限制。TikTok 开发者指南明确所有 Live API / SDK 集成都要审核，且不保证审核时长或批准结果。

项目判断：

- TikTok 可做内容生产和发布辅助，但不适合作为 P0 私信统一接入承诺。
- 若后续 TikTok 成为有效询盘渠道，再单独做官方 API PoC。

### 6.5 YouTube

YouTube Data API 支持通过 `commentThreads.list` 获取评论线程，`commentThreads.insert` 创建顶级评论，回复评论需使用 `comments.insert`。

项目判断：

- YouTube 更适合接“评论线索监控 + 回复辅助”，不适合当作私信入口。
- 第一阶段建议通过视频描述、置顶评论、频道主页引导到官网或 WhatsApp。

| 功能 | 可行方式 | 注意事项 |

### 7.3 不建议本项目第一阶段实现 / 承诺的能力

| 能力 | 原因 |
| --- | --- |
| WhatsApp 公共账号池 | 账号归属、封号、聊天记录、客户资产和合规风险高 |
| LinkedIn 私信自动化 | 普通开发者难以获得官方私信 API 权限，RPA 风控高 |
| 全平台统一私信接入 | 各平台权限、审核、账号类型差异大，容易超出 MVP |
| 全自动批量发布 | 平台风控、内容错误、账号安全风险高，必须保留人工审核 |
| 账号注册养号 / IP 矩阵 | 属于运营服务和资源能力，不是软件开发核心交付 |
| 海外 60+ 付费数据库 | 成本和授权不确定，不应在低价自研版本中承诺 |
| 保证线索数量或成交结果 | 外贸 ToB 大单转化受市场、产品、销售、价格、交付能力共同影响 |

## 8. 对当前项目方案的调整建议

### 8.1 产品定位

建议把本项目定义为：

> 建材出海企业自有的 AI 获客与运营工作台，而不是供应商式海外营销 SaaS。

这个定位更符合甲方“官网和源码归自己”“低成本跑通闭环”“后续可复制给佛山中小生产企业”的目标。

### 8.2 MVP 范围

建议 MVP 锁定：

1. 英文 / 阿语铝单板独立站 + CMS。
2. 官网 AI 客服 + 业务知识库。
3. WhatsApp 官方入站消息接入。
4. 飞书 CRM 自动入库、客户分级、跟进提醒。
5. AI 内容工作台：多语言文案、图片、视频脚本、素材库。
6. 首批 1-2 个平台的发布辅助：建议 Facebook / Instagram 或 TikTok 先做内容生成 + 人工审核 + 半自动发布。
7. LinkedIn 先做人工开发辅助，不做自动私信。

### 8.3 功能架构参考

建议按以下模块实现，后续可产品化复用：

| 模块 | 说明 |
| --- | --- |
| 企业产品大脑 | 公司资料、产品参数、案例、FAQ、销售话术、竞品、目标市场 |
| 客户画像与评分 | 国家、行业、公司类型、项目规模、意向强弱、跟进状态 |
| 统一会话工作台 | 官网、WhatsApp、后续 Meta / IG 消息统一展示 |
| AI 回复与转人工 | 多语言回复、低意向过滤、高意向摘要、人工接管 |
| AI 内容工作台 | 爆款拆解、多语言文案、图片 / 视频脚本、平台适配 |
| 发布队列 | 生成内容后进入审核，记录平台、账号、状态、发布时间 |
| 飞书 CRM | 线索入库、客户档案、跟进记录、自动提醒、客户画像 |
| 反馈迭代 | 把回复、成交、内容表现、客户质量反哺话术和评分规则 |

### 8.4 报价和沟通口径

当前 `输出/建材出海AI获客系统AI开发报价单.md` 中 V1b 26800 元的定位是合理的，但建议在对外沟通时强调：

- 我们不是复刻易飞轮 5-10 万 / 年的运营服务套餐，而是做甲方自有的可运行系统。
- 我们不是购买光年触达的全球数据库和账号池，而是先做可控的官网、AI 客服、CRM、内容和官方 / 半官方渠道接入。
- 供应商能提供的是重资源 / 重运营 / 重数据能力；本项目第一阶段解决的是“少人、低成本、能沉淀数据、能持续迭代”的自有工具。

## 9. 供应商追问清单

若后续考虑采购、合作或继续竞品调研，建议向两家供应商追问：

### 9.1 光年触达 iSales

- 全球 60+ 付费数据库分别是什么，数据授权与使用边界如何？
- WhatsApp 账号池是否基于官方 Business Platform / BSP？账号归属和封号责任如何界定？
- 客户聊天记录、联系人、营销记录能否完整导出？停止合作后数据如何处理？
- “成功找到客户”如何定义？重复客户、无效网站、无联系人如何计费？
- Email 发送使用谁的域名和邮箱？SPF / DKIM / DMARC 谁配置？退信和投诉如何处理？
- 模型训练资料是否用于其他客户？是否支持私有化或数据隔离？
- 4200+ / 8333+ / 12800+ 潜在客户的行业匹配率、回复率、有效询盘率如何验收？

### 9.2 易飞轮

- 批量发布分别对接哪些平台的官方 API，哪些依赖浏览器自动化或供应商资源？
- 账号注册养号后的账号归属是谁？手机号、邮箱、2FA、设备和 IP 归谁管理？
- “无需科学上网”的网络环境如何提供，是否包含在费用里？
- 私信评论统一管理覆盖哪些平台？LinkedIn、TikTok、YouTube 是否包含私信还是评论？
- AI 自动回复是否基于企业知识库？是否支持转人工和 CRM 字段映射？
- 广告线索入库支持 Meta Lead Ads / TikTok Lead Ads 还是人工录入？
- 12 个月服务期结束后，素材、数据、账号、内容、线索能否导出？

## 10. 最终判断

对本项目而言，最优策略不是二选一购买供应商，而是吸收两家的成熟产品逻辑，做一个更轻、更可控、更贴合建材 ToB 的自有系统。

- 参考光年触达：企业模型、客户画像、找客户评分、个性化营销、反馈迭代、算力点成本解释。
- 参考易飞轮：AI 内容生产、社媒矩阵发布、统一互动管理、运营陪跑结构、内容 / 账号 / 广告服务拆包。
- 坚持本项目边界：官网和数据归甲方，P0 先跑通官网 AI 客服 + WhatsApp + 飞书 CRM + 内容工作台，P1 再扩 Meta / IG / TikTok / YouTube，LinkedIn 维持人工主导。

这样既能向客户证明我们理解竞品能力，也能避免把供应商的资源型能力误包装成低价定制开发承诺。
