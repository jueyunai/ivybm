## 一、改版背景与核心目标

1. **定位升级**：将现有外贸“产品货架展示型”官网，升级为“欧洲高端幕墙工程一体化解决方案 + 角色决策转化”的专业国际站。
2. **转化升级**：将传统表单留言升级为以“图纸/3D/BOQ 附件上传与深化可制造性评估（Buildability Review）”为核心的高价值大单线索漏斗。
3. **GEO / AI 搜索引擎友好**：上线 `/llms.txt`、Answer-First 文案与分层 JSON-LD Schema，但不发布未经确认的认证、公差、价格、质保、固定交期或项目业绩。
4. **CMS 可持续管理**：完善产品工程流程、案例四维结构、公开知识文章与线索附件管理，保证新增内容可在 `/dashboard` 中继续编辑和优化。
5. **框架先行**：不等待客户一次性提供全部文案与图片。技术团队先基于已有素材和确认需求完成页面、字段和编辑能力，后续由客户和运营人员通过 CMS 持续补充。

6. **导航与入口收敛**：顶部 Tab 菜单移除 Home、Contact 两个直接入口（路由保留，分别由品牌 Logo、上传图纸 CTA 等其他入口访问），新增 Capabilities、For Professionals、Knowledge；右上角询价按钮统一改为“上传图纸”（英文 `Upload Drawing`，阿拉伯语提供对应本地化文案）。

## 二、已确认的实施边界

### 2.1 三类内容系统默认解耦

1. **官网 CMS 内容**：`Products`、`Projects`、`Posts`，用于公开官网展示。
2. **AI 客服知识库**：`KnowledgeDocuments`、`KnowledgeChunks`，以运营人员在后台上传的内容为准，用于客户询盘自动应答、客户初筛和人工接管。本期不自动引用或同步官网文章。
3. **AI 内容工作台**：`GeneratedContents`、`ContentReviews`、`PublishJobs`、`PublishLogs`，用于 AI 内容生成、人工审核和用户触发的社媒 API 发布。

三者不建立强外键、不自动同步、不因 CMS 保存而触发 AI 生成或社媒发布。后续如需复用，应另行设计用户明确触发的导入动作。

### 2.2 新增字段可空且向后兼容

- 新增 CMS 字段默认允许为空，不强制一次性补齐旧数据。
- 前台只渲染已有内容的区块，不展示空标题、占位参数或虚构事实。
- 社媒入站创建 Lead 时，`projectStage`、`quantitySquareMeters`、`timeline`、`hasDrawings`、`attachments` 等字段均为可选项；飞书字段不存在时跳过写入，不得因缺失官网询盘字段阻断社媒 Lead。
- 继续保留现有 Lead 基本联系不变式：至少存在一种有效联系方式，或完整且已经服务端验证的社媒身份。

### 2.3 内容与多语言策略

- 英文作为内容基线，技术团队可依据客户需求、现有素材和新版 Demo 撰写通用英文框架文案。
- 阿拉伯语优先使用机器/AI 在本地从英文翻译，完成技术术语抽查、RTL 和页面 smoke 后上传。页面可在缺字段时回退英文以保证可用性；只有阿语标题与主要正文/结构化主字段达到最小完整度时，才输出 `hreflang="ar"` 和阿语 sitemap 条目，避免把英文回退内容伪装成完整阿语页面。
- 不把“等待客户提供专业阿语翻译”作为开发或首版上线的阻断条件；上线后可在 CMS 中持续修订。
- 认证、公差、价格、质保、固定交期和项目规模等事实性承诺必须来自已确认资料，不得由 AI 或技术团队自行补全。
- 阿语页面中的型号、尺寸、单位、认证编号和英文缩写统一使用 `dir="ltr"` 隔离容器；页面整体仍保持 RTL，避免 BiDi 标点和数字错乱。

### 2.4 本轮客户确认的视觉与导航原则

- 官网继续使用现有深蓝色品牌配色；新版 Demo 中的红黑配色不作为本期改版要求。
- Capabilities、For Professionals 两个模块保留并进入顶部导航；首版先完成页面框架、信息层级和可编辑入口，后续再逐步补充详细素材。
- Knowledge 作为独立公开内容模块新增，不覆盖、不替换现有 News；现有 `/news` 路由、文章和旧链接继续保留。
- 顶部导航固定为 `Products → Capabilities → Projects → For Professionals → Knowledge → News → About`；移除 Home、Contact 两个 Tab，但不删除对应页面路由。Home 通过 Logo 或其他 CTA 进入，Contact 询盘入口统一收敛为“上传图纸”。
- 运营后台需要为 Capabilities、For Professionals、Knowledge 提供可见、可编辑、可发布的内容管理模块；默认复用现有 Pages/Posts 能力，不因模块拆分重复创建内容 Collection。

## 五、素材基线与渐进式上架原则

### 5.1 已确认的线上基线

- 以线上已经客户确认的 **16 个产品、71 个项目**为唯一内容与 URL 基线（已确认业务口径；历史计划文档中“3 产品/8 项目”为当时上架中间态记录，不作为基线口径）。阶段 0 的 production 快照**仅用于核对线上是否发生数据漂移，不用于重新决定数量口径**。
- 本地客户素材包视为该基线的全量源素材，不再按新产品/新案例重复建立文档。
- 素材包产品与案例源文档经去重、合并和已有案例复用后，映射到线上基线项目。
- 新版开发以“升级现有内容结构和展示模板”为主，不创建重复 slug、重复产品或重复项目。
- **阶段 0 冻结产出：素材映射清单**（已确认交付物）：18 份产品详情文档→16 个基线产品、69 份案例源文档→71 个基线项目的逐条对应表，作为正式交付物；两组数字不是一对一新增关系，案例清单必须标明源文档经合并、补充和既有项目复用后的动作（`create`、`enrich-existing`、`merge-into-existing`、`merge-into-product`、`ignore-duplicate`），并记录目标 slug、依据和待核验字段。当前口径为 69 份案例源文档形成 63 个新增项目，另复用 8 个既有项目，共 71 个线上项目；如清单核对发现不一致，先记录差异，不擅自改变 16/71 基线。内容批量导入**复用现有 `scripts/content-import` 幂等导入器**（已支持 manifest SHA、dry-run、checkpoint、幂等 upsert），不重建导入逻辑。完成定义（DoD）增加“映射清单存在、动作齐全且无重复 slug”验收项。

### 5.2 技术团队首批责任

- 依据已有素材和新版 Demo 完成首页、Capabilities、For Professionals、双曲铝板页和 Knowledge 的框架文案。
- 将已有 16 个产品和 71 个项目逐步映射到新字段和新模板；允许先完成代表性页面，其余条目在 CMS 中渐进式补齐。
- 生成首批英文框架文案和对应阿拉伯语机器翻译，完成英文/阿拉伯语页面、移动端和 RTL 验证。**阿语读取采用英文回退策略**（技术默认值）：将 `website-data.ts` 查询中的 `fallbackLocale: false` 改为 Payload 支持的英文回退值（建议 `fallbackLocale: 'en'`），阿语缺字段/缺文章时回退显示英文内容，页面不 404；只有达到最小阿语完整度的页面才进入 `hreflang="ar"` 与阿语 sitemap，翻译补齐后自然加入索引。
- 部署 `/llms.txt`、Organization/Product/Article/FAQPage 等适用的 JSON-LD，并验证 canonical、hreflang 和 sitemap。

### 5.3 后续渐进补充的内容

以下内容不阻断首版框架开发，但在对应事实性区块对外发布前仍需要可核验的资料：

2. 材料对比、双曲加工流程、采购指南、质检标准等专业文章的进一步资料。
3. 产品规格、案例地点/年份/用量/范围、公差、认证、质保和交期等可公开事实。
4. 上线后发现需要修订的阿拉伯语术语、文案和排版。

### 5.4 阿语术语表（增强项，待业务确认）

阶段 3 建立英阿核心术语对照表（幕墙、铝板、公差、深化等核心术语），作为文档资产沉淀；机器翻译抽查和后续内容补齐的翻译校验均以术语表为准，防止渐进补齐期同一术语前后译法漂移。

### 5.5 成功指标基线（技术默认值）

上线前记录询盘量与表单完成率基线；上线后按月跟踪附件提交率与 Lead 总量。**Lead 来源归因分布仅在来源字段增强项启用并完成数据回填后统计**，未启用前不得以缺失来源数据计算该指标。无新基建，用现有日志与 Portal 数据即可。指标用于验证“定位升级、转化升级”目标是否达成，并指导渐进补齐优先级。

## 六、询盘附件安全与运营边界

1. 客户图纸、BOQ、CAD/3D 文件视为私有商业资料，默认不公开、不进入网站图库、不生成公开 CDN URL。
2. 只有已登录且具备线索访问权限的 admin/operator/sales 才能下载。
3. **飞书附件链接**（已确认）：附件不作为文件直接写入飞书多维表格，而是把下载链接写入飞书表格；链接为**永久稳定链接**（指向 Portal 附件页，不设时效、不需后续更新），下载必须经 Portal 登录与线索权限校验后提供，匿名访问不能下载；附件超过保留期被清理后，链接提示附件已按保留策略清理。
4. 上传接口必须保留现有询盘幂等、频率限制和失败返回语义；附件上传失败时必须明确告知客户，不得伪报图纸已提交。前端在选文件时立即执行扩展名/大小校验；每个文件显示真实上传进度、取消和单文件重试，默认请求超时 **120 秒**，失败不得强迫客户重新选择整批文件。附件使用匿名时效 token 暂存上传（技术默认值）：token 有效期默认 **2 小时**，与签发会话绑定并记录来源 IP 用于频率限制（不强制单一 IP 绑定，避免移动网络切换误伤）；暂存文件 **24 小时**未关联 Lead 即可清理。
5. **保留与删除由手动维护脚本兑付**（已确认：纳入本期，但不新增线上定时调度）：附件记录写入 `expiresAt`；提供 `scripts/` 清理脚本，由运维/开发者按需手动执行（建议每月及上线检查点），删除超 180 天的已关联附件与超 24 小时未关联的暂存文件，每次删除写审计日志，并支持 dry-run、删除统计和失败返回码，便于纳入现有运维检查清单。与冲刺基线的调度冻结一致，不扩展通用调度平台或无人值守流程。`legal.ts` 隐私声明同步更新 180 天附件保留规则、上传同意与跨境发送告知。
6. 上线前必须验证文件类型、容量、超限错误、未登录/越权访问附件链接、Lead 关联降级、附件清理后的链接提示、Portal 下载和飞书表格链接写入；若启用 Portal 附件徽标/筛选，列表查询必须按当页 Lead ID 批量聚合附件数量，禁止循环内逐条查询。
