# 平台账号页 UI 验收简报

## 目标体验

目标用户是低频配置平台账号的管理员。页面应让用户感到“可控、清楚、不会误发消息”，而不是看到平台 API 的内部状态表。

## 截图暴露的问题

- 编辑字段、帮助文案和审核状态拥挤在同一行，标签与输入框边界不清。
- 连接、编辑、删除并列，破坏性操作过于突出。
- “连接状态 / 入站消息 / 内容发布”重复展示相同缺口和下一步。
- 平台审核术语和技术 ID 抢占主视觉，用户看不到 AI 是否会自动回复。
- 卡片过宽但内容没有使用清晰栅格，桌面端反而比移动端更难扫读。

## 视觉方向

- 延续仓库现有 Digital Lattice：低饱和紫、深灰文字、白色 Surface、1px 边界。
- 不采用 UI 技能生成的“鲜红 CTA / vibrant block”建议，因为与现有 Portal 品牌和高风险配置场景冲突。
- 状态采用 compact badge + 一句话说明；主要操作最多一个，其他操作进入“管理账号”。
- 表单进入 modal/drawer，桌面双列、移动单列；危险操作独立分区。

## 响应式断点

- 1440px：账号摘要可使用两列信息区，状态行保持完整。
- 1024px / 768px：卡片单列，操作区允许换行但不挤压状态。
- 390px / 375px：全部单列，按钮全宽或明确分组，无横向滚动。

## 状态矩阵

| 状态 | 卡片文案 | 主要操作 |
| --- | --- | --- |
| 未连接 | 账号尚未授权 | 连接 |
| 已连接、入站未批准 | 需完成私信权限 | 重新授权 / 查看诊断 |
| 已连接、AI 暂停 | 消息继续进入后台，AI 不回复 | 恢复 AI 回复 |
| 已连接、AI 开启 | AI 会自动回复新消息 | 暂停 AI 回复 |
| 保存中 | 正在更新设置 | 禁用重复操作 |
| stale revision | 账号信息已更新，请刷新后重试 | 刷新 |

## 可访问性

- 状态切换拥有账号上下文的 accessible name。
- 成功/错误通知可被屏幕阅读器感知。
- 对话框具备标题、描述、焦点圈、Esc 与焦点回收。
- 状态文本对比度至少 4.5:1，颜色不是唯一信息。
